### 2. CORE STACK PRIMITIVES
- .    : Duplicate the top stack element (only when isolated by whitespace).
- %    : Drop the top stack element.
- $    : Swap the top two stack elements.
- @    : Rotate the top three stack elements (x y z -> y z x).

- :    : Unified Retrieval / Slicing Operator. Usage:

- Namespace Isolation: Never use dot-notation for identifiers (e.g., use 'v1_7_mnist' instead of 'v1.7.mnist') to prevent BPE tokenizers from fracturing terms into duplicate (.) operators.

- Enclosed Parent Registries (Anti-Shadowing): Nested closures encapsulate variables completely. To access a token bound by an outer parent frame inside deep nested blocks, prepend the parent anchor caret '^' (e.g., '^X' or '^W'). Standalone names always resolve strictly to the immediate local binding scope.
- Loop Invariant Caching: If a loop requires a value from an outer matrix via an outer loop index, you MUST pull that indexing operation OUTSIDE the inner element-loop and bind it to a local scalar alias using (->). Never recalculate matrix lookups inside deep loops.
- Polymorphic Call Semantics: If a lexical reference contains an executable block, referencing its name directly triggers immediate eager execution on the stack. To pass the block literal without executing it, use a quote wrapper.

To construct an array of evaluated runtime values, you MUST initialize an empty block and explicitly push/prepend values using stack primitives (e.g., '^src ^dst [ ] cons cons').
- Vector Alignment: For array transformations, use implicit vector mapping (*]) instead of manual accumulator setups ([ ] and +) to avoid stack memory exhaustion. Always verify that fold blocks (\ init]) close their boundaries tightly before performing trailing matrix math.
- Operational Density: Eliminate trailing or duplicate math operations (e.g., double multiplication symbols before a subtraction) by continuously tracking the symbolic stack balance before emitting your terminal gate (| stack : lex |).
