═══════════════════════════════════════════════════════════════════════════
THE SEVEN RULES THAT MOST OFTEN BREAK CODE — obey these first
═══════════════════════════════════════════════════════════════════════════
1. FRAMES ARE ALWAYS `-> [ vars ] [ body ]` — two bracket groups. A frame followed
   by loose tokens (`-> [ x ] x 1 +`) is a PARSE ERROR. The body is always bracketed.

2. CONDITIONALS ALWAYS USE THE `cond` KEYWORD: `flag cond [ t ] else [ f ] ?`.
   Bare `flag [ t ] else [ f ] ?` (no `cond`) is ILLEGAL. There is no shorthand.

3. NO RESERVED WORD MAY BE A PARAMETER OR ALIAS NAME. Reserved: use lexicon to from
   and or not cond else map fold pk select nil cons pair end fill len seed rand exp
   log pow sqrt abs max min bitand bitor bitxor bitshl bitshr bitnot hnew hread
   hwrite print_char print_int roll. (e.g. never `-> [ end ]` or `#f ( pair -- )`.)
   Rename to a non-reserved word (`stop`, `pr`, ...).

4. POINTERS ARE OPAQUE. Never do arithmetic on a Ptr (`ptr 1 +`). Compute an integer
   offset first, then use it: `ptr offset hread`, never `(ptr+1) hread`. Ptrs come
   only from `hnew` and are consumed only by `hread`/`hwrite`.

5. NO NESTED DATA LITERALS. A block containing another block is a CLOSURE, not a
   nested array. Build nested/tree data at runtime with `cons`/`pair`, never as a
   literal like `[ 1 [ 2 3 ] ]`.

6. ITERATOR BODIES HAVE FIXED CONTRACTS AND ARE CHECKED INTERNALLY:
   `[map| idx val ctx | body ]`   body must be ( idx val -- val' ), net +1.
   `[fold| idx acc val ctx | body from init ]`  body must be ( idx acc val -- acc' ).
   A fold's return type is inferred from `init` (`from 0` → Scalar, `from nil` →
   Block); the body's produced accumulator type MUST match that init type.
   Iterators cannot contain nested brackets — factor loop logic into named words.

7. `cond` BRANCHES MUST HAVE EQUAL NET STACK EFFECT (and equal type effect). If one
   branch nets +1, so must the other. Branches cannot contain nested brackets;
   push branch logic into separate named words.

═══════════════════════════════════════════════════════════════════════════
1. STRUCTURE, WORDS, MODULARITY
═══════════════════════════════════════════════════════════════════════════
- Zero-nesting: no `[` inside an active bracket pair. Nesting depth inside any block
  is capped at 1. Sibling blocks on the same line are fine.
- Words: `#name ( inputs -- outputs ) body end`. Empty bodies legal. Signatures are
  verified for arity/type but do NOT bind names — any parameter used by name must be
  bound in an initial `-> [ ... ]` frame.
- `-> [ vars ] [ body ]`: pops values into read-only aliases for the body. Consecutive
  frames inherit unshadowed aliases (sibling scope chaining), including into a
  trailing `cond`'s branches (frame-visible-conditional carve-out).
- Forward references and mutual recursion are legal (two-pass compilation).
- Isolated imports: `use "lexicon"` at the top of a file. It is stripped from the
  executable stream and injects ONLY that lexicon's signatures from the manifest.
  Importing one lexicon does not make another's words visible — declare every
  dependency you call, or the arity pass halts on the unknown word.

═══════════════════════════════════════════════════════════════════════════
2. DUAL-TRACK STATIC VERIFICATION (what the checker enforces)
═══════════════════════════════════════════════════════════════════════════
- Track 1 (arity): each body's net push/pop must equal its signature. Literal +1;
  each primitive has a fixed effect. Call sites trust declared signatures (makes
  recursion decidable). Unknown words halt (lexical soundness).
- Track 2 (coarse types): four tags — Scalar, Block, Ptr, Unknown. `+` needs two
  Scalars; `:` needs Block+Scalar; `hread` needs Ptr+Scalar. Unknown is the escape
  hatch for values coarse tags can't decide (e.g. iterator elements) — it passes
  without false positives, so nested-element mismatches are NOT caught and must be
  reasoned about manually.
- TCO: terminal self/mutual recursion (including inside a terminal cond branch) is
  flattened to a loop. Sound because Track 1 proves the call-site stack matches the
  callee's entry. Write loops as tail-recursive words, not as a core construct.

═══════════════════════════════════════════════════════════════════════════
3. DATA TYPES
═══════════════════════════════════════════════════════════════════════════
- Scalar: 64-bit int (42, -5; negatives have no leading space) or float mantissa
  (314e-2 = 3.14). Mixed ops promote to float.
- Ptr: opaque heap token from `hnew`. No arithmetic (see rule 4).
- Block: `[ ... ]`. All-literal/empty block = immutable data array; a block with any
  bracket, operator, or alias = deferred closure (see rule 5).
- nil: the empty array.
- Comments: `{ ... }`.
