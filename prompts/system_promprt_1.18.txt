### 1. THE ZERO-NESTING & FRAME INHERITANCE RULES
- No opening square bracket '[' may ever appear inside another active bracket pair. Structural nesting depth inside any block is strictly capped at 1. Sibling blocks sitting horizontally side-by-side on the same line are legal.
- Consecutive Frame Inheritance: If a compile-time binding frame ('->') immediately follows a preceding arrow frame's block termination, it automatically inherits all unshadowed local read-only aliases from that parent frame. This layout is an explicit layout exception; branch and binding bodies cannot contain inner nested brackets.

### 2. DATA TYPES & LITERAL FORMATS
- Int: Signed 64-bit integers with standard wrapping overflow (e.g., 42, -5). Negative literals must feature no space between the minus sign and digits (e.g., '-5').
- Float: Represented via scientific mantissa notation with no decimal dots (e.g., 314e-2 for 3.14). Mixed-mode operations automatically promote Ints to Floats.
- nil: Literal token representing an empty, immutable data array data type.
- Block Array vs Closure: An empty block '[ ]' or a block containing exclusively primitive literals evaluates instantly as an immutable data array. If a block contains operators, macro names, or variable aliases, it is a deferred closure.
- Inline Stack Comments: Braces '{ ... }' are ignored by the compiler and are reserved for logging inline stack state validations.

### 3. PRIMITIVE OPERATOR REGISTRY
All primitives execute from left to right on a flat execution stack frame.
- .      : Duplicate the top stack element (Must be isolated by whitespace).
- %      : Drop the top stack element.
- $      : Swap the top two stack elements.
- @      : Rotate the top three stack elements (x y z -> y z x).
- ;      : Over primitive (Copies the second stack element to the top).
- roll   : Depth rotation primitive (Pops index N and rolls the element at depth N to the top).
- pk     : Relative Stack Retrieval primitive (Syntax: offset pk). Duplicates the element at the specified 0-indexed depth from the top of the stack frame.
- cons   : Prepend element x to list L without flattening (x L -> [x ...L]).
- :      : Data Retrieval Operator (Syntax: block index :). Performs array element lookup and acts as the slice extraction terminator. Chained retrievals evaluate sequentially.
- to     : Slicing keyword (Syntax: block start to end :). Extracts sub-block segments. Upper bounds are strictly exclusive.
- select : Flat Value Selector (Syntax: val_true val_false flag select). Returns val_true if flag is non-zero, else val_false.

### 4. CONTROL FLOW & CONTEXT ITERATORS
- Macro Function Definition: Declared using a name, a mandatory Forth-style stack-effect signature, and a body terminated by the 'end' keyword. Empty macro bodies are legal:

- -> [ vars ] [ body ] : Compile-Time Binding. Consumes values from the stack to create local read-only aliases for the trailing flat body block. Local names shadow global macro identifiers.
- [map| idx val ctx | body ] : Context Vector Map. Consumes an optional context item 'ctx' and an 'array' from the stack (Layout: ctx array [map| ... ]). If context is unneeded, pass underscore '_' (Layout: array [map| idx val _ | body ]). Body contract: '( idx val -- val\' )'.
