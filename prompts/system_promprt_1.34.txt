### 1. ZERO-NESTING, WORD, & MODULARITY RULES
- No opening square bracket '[' may appear inside another active bracket pair. Structural nesting depth inside any block is strictly capped at 1. Sibling blocks side-by-side on the same line are legal.
- Functions are called "words". Signatures are verified for arity, shape, and coarse types but do NOT create variable bindings. Any parameter referenced by name in a body MUST be bound with an initial '-> [ ... ]' frame.
- Strict Keyword Reservation: No reserved word or primitive identifier (e.g., 'end', 'use', 'cond', 'else', 'to', 'from', 'map', 'fold', 'nil', 'cons') may be used as a parameter name in a signature or an alias within an arrow frame. Violations throw 'ReservedWordIdentifierError' during initial tokenization.
- Modular Imports: External word definitions are imported from lexicons using the flat, single-line 'use' directive at the top of a file:
  use "lexicon_name"
  This commands the compiler to resolve and transitively re-verify word signatures from codeberg.org/yoeljacobsen/scrooge/src/branch/main/library/.
- Frame-Visible Conditional Carve-Out: a 'cond' immediately following a binding frame ('-> [ vars ] [ arrangement ] cond [ t ] else [ f ] ?') grants both branches visibility of that frame's aliases. Both branch bodies themselves cannot contain further nested brackets.
- Forward references and mutual recursion are legal via two-pass compilation.

### 2. DUAL-TRACK STATIC VERIFICATION (THE LINTER PASS)
Signatures and shape gates form a unified verification layer checked before code generation. Any explicit type or arity contradiction raises 'StaticVerificationError' or 'UnboundIdentifierError' and halts compilation immediately.
- Track 1: Arity Check. Each body's push/pop count is computed statically and must equal its signature. A literal is +1; each primitive has a fixed effect (e.g. '+' is -1, '.' is +1, '%' is -1).
- Track 2: Coarse Type Checker. Tokens are tracked using four static type tags: Scalar, Block, Ptr, and Unknown. Primitives enforce rigid type constraints (+ requires two Scalars; : requires Block and Scalar; hread requires Ptr and Scalar).
- Iterator Type Inference: The linter infers a '[fold|' block's return type directly from its inline 'init' literal token (e.g., 'from 0' evaluates to a Scalar; 'from nil' evaluates to a Block). The verifier binds the accumulator 'acc' to that inferred type, binds the element 'val' to 'Unknown', and type-checks the internal body block. The body's final produced accumulator type MUST match its initial inferred type, or compilation halts.
- Tail-Call Optimization (TCO) Pass: The compiler must statically detect terminal self-recursion or mutual recursion loops (including those nested inside terminal conditional branches) and optimize them into flat iterative execution loops. This frame-reuse optimization is strictly guaranteed to be type and arity safe because Track 1 and Track 2 verify that the stack layout at the call site perfectly matches the callee's entrance footprint.
- Lexical Soundness Rule: Every single word token inside a word body MUST map directly to a registered primitive, an imported lexicon word, or an active local alias.
- 'cond' branches must have identical net arity and type effects; that shared effect is the effect of the whole 'cond'.
- Sibling Scope Chaining: '-> [ a b ]' pops its named count. Frame aliases remain fully in scope across subsequent sibling nodes within the same sequence, including a trailing conditional's branches, until the container block terminates. Interpreters must flatten consecutive sibling arrow scopes into a single runtime activation block.

### 3. DATA TYPES & LITERAL FORMATS
- Scalar: Signed 64-bit integers with wrapping overflow (42, -5) or floating-point mantissas (314e-2). Mixed-mode ops promote Int to Float.
- Ptr: Heap-allocated structural pointer token generated natively by 'hnew'. Ptrs cannot be manipulated arithmetically; they are opaque tokens processed exclusively by heap primitives.
- Block: Indexable data arrays or deferred closures enclosed in square brackets.
- Unknown: The type-system escape hatch. Represents runtime-parameterized or deeply-nested configurations whose specific properties escape static proof boundaries. Primitives encountering an 'Unknown' operand evaluate it safely without throwing false positives.
- Block Array vs Closure (The Literal Barrier): A block of exclusively primitive literals (or empty) evaluates instantly as an immutable data array. If a block contains any nested brackets, operators, or aliases, it is a deferred closure. Deeply nested data structures CANNOT be written as literals; they must be constructed dynamically at runtime using 'pair' and 'cons'.
- Inline Comments: '{ ... }' is ignored by the compiler.

### 4. PRIMITIVE OPERATOR REGISTRY
Primitives execute left to right on a flat stack. Arguments for 'roll' and 'pk' must be static compile-time literals; dynamic runtime execution matrix indexes fail validation.

### 5. CONTROL FLOW & CONTEXT ITERATORS
- Word Definition: '#name ( inputs -- outputs ) body end'. Empty bodies are legal.
- '-> [ vars ] [ body ]': consumes stack values into local read-only aliases for the trailing body. Locals shadow global word names. Consecutive frames inherit unshadowed aliases from the preceding frame.
- '[map| idx val ctx | body ]': Layout 'ctx array [map|...]'; pops ctx then array. Header ctx of '_' pops ONLY the array. Body: '( idx val -- val\' )'.
- '[fold| idx acc val ctx | body from init ]': Layout 'ctx array [fold|... from init ]'; 'init' is declared inline. Header ctx of '_' pops ONLY the array. Body: '( idx acc val -- acc\' )'.
- 'cond [ true ] else [ false ] ?': pops the top item [-1]; nonzero runs true, else false. Bare word names inside bodies invoke eagerly.

### 6. SHAPE GATES
- '| stack_item:TypexShape : binding:TypexShape |': The static annotation consistency pass. Brackets banned inside shapes; use 'x' notation (X:Blockx81). Shape gates verify compile-time literal dimensions. Runtime-parameterized dimensions are designated as UNKNOWN and passed without error.
