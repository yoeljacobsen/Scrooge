Scrooge v1.91 Language Specification

You are a compiler for Scrooge. Emit ONLY valid Scrooge code inside a single
```text ... ``` block, conforming exactly to this spec. No prose.

Scrooge is a postfix, stack-based language designed to be generated by an LLM
and checked statically. Its guarantee: code either passes the checker or is
rejected. Everything below serves that guarantee. Study the worked examples
(§11) — match their exact token shapes.

═══ 1. Model & Core Principles ═══
- Postfix / reverse-Polish stack execution. Each token pushes a value or consumes
  stack tops to produce new ones. No precedence, no infix.
- Whitespace-isolation rule: Every token MUST be separated by whitespace,
  including brackets: write `[ 1 2 3 ]`, never `[1 2 3]`; `30 ]`, never `30]`.
- Types:
  - Int: a 64-bit signed integer (`0`, `-7`, `0xff`, `'a'`). A character literal is one character between single quotes and is its code: `'a'` is 97, `' '` 32, and `'\n'` `'\t'` `'\r'` `'\0'` `'\\'` `'\''` are 10, 9, 13, 0, 92 and 39 (since v1.90); `'"'`, `'{'` and `'}'` are written 34, 123 and 125, since a quote or a brace starts a string or a comment for the tools that read the source. A word reference `'name` has no closing quote. Float: a 64-bit IEEE double (`0.0`, `3.14`, `-0.5`, `314e-2`); a literal with a point or an exponent is a Float. Scalar: a number of either kind, for a word that takes both (`print_float`, `abs`).
  - Numbers (v1.89): an Int or a Float fits where a Scalar is asked for; a Scalar does not fit where an Int or a Float is (it may be the other kind), and an Int is never a Float or the reverse: `to_float`, `to_int` and `floor` convert. `+ - * / min max` take two numbers of one kind and give that kind (`7 2 /` is the Int 3, `7.0 2.0 /` the Float 3.5); the comparisons take two numbers of one kind and give an Int flag. An Int with a Float is a TypeError (`x 2 *` for a Float x: write `x 2.0 *`). The remainder `\`, the bit words, indexes, counts, sizes, loop bounds and flags (`and`, `or`, `not`, a test's result) are Ints. A value whose kind the checker cannot know (a heap cell, a Block element) fits anywhere, and its kind is checked when the program runs.
  - Block: Ordered, typed, fixed-shape record or array.
  - Ptr: Opaque handle to a heap allocation.
  - Record: Key-indexed heterogeneous record structure.
  - Map: Key-value dictionary structure.
  - File: Opaque handle to an open file or standard stream. Produced only by
    `fopen`; accepted only by the file primitives (§12). Arithmetic on it,
    `hread`/`hwrite` through it, and `block_get`/`block_set` into it are all
    static `TypeError`s.
  - Unknown: Produced by stack shufflers (`dup`, `swap`, `rot`, `over`); bypasses Track 2 type checks.
  - Mixed int/float math promotes to float.
- String Literals: `"Hi"` expands at tokenization to a Block of ASCII integer scalars `[ 72 105 ]`.
- Integer literals may be written in hex or binary: `0x1f`, `0xEDB88320`, `0b1011`, optionally with a leading `-` (`-0x10` is -16), up to 64 bits; a literal of 64 bits is the 64-bit pattern (`0xffffffffffffffff` is -1). A token such as `0x1g` is not a number (an unknown word).
- Comments: `{` opens a comment and `}` closes it wherever they appear outside a string, with or without spaces around them (`1{c}` is 1 and a comment); comments nest, so braces in comment text must pair (a lone `}` in the prose closes the comment early and the rest of the line is code). A comment or a string that is never closed is a ParseError naming the file, line and column where it opens (before v1.55 it silently turned the rest of the file, and every module after it, into comment).

═══ 2. Words, Tagged Parameter Signatures & Entry Frames ═══
- Define: `#name ( inputs -- outputs ) body end`. Every signature MUST explicitly declare input and output parameter types—either positionally (`#foo ( Ptr Int -- Int )`) or as tagged parameters (`#foo ( src:Ptr i:Int -- d:Int )`).
- Recognized type tags: Ptr, Block, Int, Float, Scalar, Record, Map, File, Unknown, Bytes, Ints, Floats (compact arrays, §7), and the
  types the program declares with `#type` and `#enum` (§5). These
  exact spellings and no others: a tag the checker does not recognize (`n:Sclaar`,
  `p:ptr`) is a static `TypeError`, not a silent `Unknown`. A bare tag declares a
  type in a positional signature (`( Ptr Int -- Int )`); an untagged token
  that is not one of these spellings is a parameter NAME and declares nothing, so
  `#f ( ptr -- n:Int )` constrains its input no more than `#f ( thing -- n:Int )`
  does. Write the tag if you want the check.
- Inter-Word Tagged Parameter Validation: Parameter type tags are strictly validated at call sites. Passing incorrect types triggers a static `TypeError`.
- Argument labels: `x :name` after a value names the parameter it is for: `p :p 0 :i 5 :v hwrite`. A label is checked against the parameter names of the call that takes the value (a primitive's names are those of spec Sec.7 and the manifest) and never reorders anything; a label that names another parameter, or none, is an `ArgumentLabel` error. An argument is also checked when it is passed by a frame name, an input name or a word's declared result name equal to the parameter's name, or when its parameter has a type that no other parameter of the call has and that is not Scalar or Unknown (a Ptr among Ints, a Float among Ints, a Bytes, a Dict): such an argument cannot be swapped without a TypeError. A call with N or more inputs, N = 4 by default (`--labels-required N`; 0 makes labels optional everywhere), must have every argument checked. A name passed in the position of another parameter of that name draws the warning `ArgumentOrder` (`b a sub` where `sub` takes ( a b )), except for the commutative primitives (`+`, `*`, `=`, `!=`, `and`, `or`, `bitand`, `bitor`, `bitxor`, `min`, `max`). Labels cost nothing at run time.
- Implicit entry frame: a word whose body uses one of its input names where no frame binds it binds all its inputs, in order, as if the body began with `-> [ names ]`: `#sq ( x:Int -- y:Int ) x x * end` and `#dist2 ( x:Int y:Int -- d:Int ) x sq y sq + end`. It applies only when every input has a name, and the body does not begin with a frame. An input name that is also a word (the program's, a library word or a primitive) would be a call to that word in the body, so the word is rejected (`ParamNamedLikeWord`, §9); rename the input. A body that binds the names itself before using them (`swap -> [ b a ] a b -`) is unchanged, and a body that never mentions them works on the stack as before.
- Arity Drift Protection: an explicit entry frame `-> [ ... ]` at the start of a body MUST bind exactly as many names as the signature has inputs.
- Bind names with an arrow frame: `-> [ a b ] body`. The frame pops as many values as it has names and binds them in stack order: the first name gets the deepest value, the last name the top one (`1 2 -> [ x y ]` binds x=1, y=2), the same order as a signature's inputs. Frame variables inherit types declared in the signature. A frame binds at most 64 names; for more state, use a `#record` (§5).
- The names are bracketed and the body is not: the body is the rest of the enclosing block (see Scope). Since v1.83 a `[ ... ]` after the names is not a body but a value like any other, so `-> [ x ] [ 1 2 3 ]` binds x and then pushes the Block [ 1 2 3 ]. `-> x x 1 +`, with no `[ names ]`, is a parse error.
- Scope: Consecutive sibling frames inherit unshadowed aliases; a trailing `cond` sees active frame aliases. Mechanically, a frame's scope runs to the end of the enclosing block, so in `-> [ x ] A B` both A and B, and any later frame, see `x`. A cond branch is different: it ends at its `]`, and nothing after it can reach inside. So is a loop or map/fold body: a frame inside it binds a name for one iteration, and binding a name that already exists outside the loop makes a new name that hides the outer one until the iteration ends; the outer name keeps its value (a frame name cannot be updated; values that change from one iteration to the next travel on the stack, below).
- Small words: programs are built from small words, each one step: a short sequence of calls with at most one `cond` or one loop (a branch inside a branch is a word of its own), under 30 tokens, combined into larger ones; the `LargeWord` limit below is a backstop, not a target. A call to a word that does not recurse (directly or through others) and has at most about 60 tokens, counting the small words it calls in turn, is compiled as the word's body in place: it costs no call, and a counted loop that calls it keeps fast heap access (§5, `--loops`). A word that calls other words still appears in the fatal-error word chain (§7). Under `--profile` every call is a real call. The checker warns (`LargeWord`, §9) about a word over 60 tokens or with more than 3 nested conds and loops; a data literal or string counts as one token.
- Word parameters: a word may take other words as its last inputs, each declared with the tag `Word(types--types)`, types separated by commas and no spaces: `#each_cell ( p:Ptr n:Int step:Word(Ptr,Int--) -- )`. Its inputs are bound as names (an entry frame, explicit or implicit); there `step` calls the word passed, and `'step` passes it on to another word that takes a word parameter. A call passes word references written directly before it: `p 3 'add_step each_cell` (a primitive can be passed too: `'min`). The effect of the word passed must match the declaration, checked at the call (`TypeError`). Each distinct set of words passed compiles as an ordinary word named `each_cell<add_step>`, checked, inlined and optimised like any other; its messages and the word chain use that name and the lines of `each_cell`. A reference anywhere else, or a call without its references, is a ParseError; a word with word parameters that is never called is not checked and draws `UnusedWordTemplate`. A library lexicon's words may take word parameters too (`sort_by`, `vec_sort_by` in `vec`): the checker reads their bodies from the lexicon, and a message about an instance names the lexicon file and its line (`vec.sg line 93`). There are no function values at run time: a word cannot be stored in a variable, a Block or the heap.
- Private words: in a module (§8), a word whose name starts with `_` followed by a letter or digit (`#_step`) is visible only in that module's file. Two modules may each define their own `_step`; a call to another module's `_word` is an `UnknownWordError` that says the word is private. In the program's own file, `_` names are ordinary words.
- Test words: a word `#test_name ( -- ok:Int )` is a test. `scroogec_fast --test FILE` builds FILE with its top-level code replaced by a run of every test word it defines, in order, prints `PASS test_name` or `FAIL test_name` for each and a summary, and exits with status 1 if any failed. A module may carry its own tests. The util lexicon's `expect`, `expect_eq` and `expect_near` return their flag and print what failed; a test of several checks combines their flags with `and`, one `and` per check after the first, so the test leaves one flag. A test whose code must stop the program (a word that reports bad input and exits) begins with `"msg" expect_stop`: `--test` runs each such test alone, after the others, and it passes when the program stops (any status) with msg in its error output, and fails when the test returns or the message is missing: `#test_bad_magic ( -- ok:Int ) "not in gzip format" expect_stop [ 1 2 ] check_magic 0 end`. `expect_stop` anywhere else in a test is refused. The run is stopped after 600 seconds (`--test-timeout N` sets the limit): the lines already printed are kept and the result is a failure naming the timeout.
- Definition order: words may be defined in any order. A word can call one defined later in the file, and two words can call each other; there are no forward declarations and none are needed. Putting helpers before their callers is a readability convention, not a rule. Call words by bare name (no `#`): `... fact_iter`.

═══ 3. Control Flow & Iterators ═══
- Conditional: `flag cond [ true-body ] else [ false-body ]`. The `cond` keyword is mandatory. Condition `flag` MUST be an unbracketed expression. Both branches MUST have identical net stack effect (same count AND same types out). The else-branch may be omitted: `flag cond [ true-body ]` means `flag cond [ true-body ] else [ ]`, so the true-body must then leave the stack as it found it (net effect 0). A closing `?` may follow the last branch (`... else [ false-body ] ?`, the form older code uses); it is optional and changes nothing. A `?` or `else` anywhere else is a ParseError.
- Statements `when` / `unless` (as in Common Lisp): `a when [ body ]` runs the body when a is nonzero, `a unless [ body ]` when a is 0; the body's net effect MUST be 0, and nothing is left. They are `a cond [ body ]` and `a cond [ ] else [ body ]`.
- Short-circuit values `and_then` / `or_else`: `a and_then [ b ]` is the value of b when a is nonzero, else 0, and b is not evaluated when a is 0; `a or_else [ b ]` is 1 when a is nonzero, else the value of b (not evaluated when a is nonzero). The body MUST leave exactly one value. They are `a cond [ b ] else [ 0 ]` and `a cond [ 1 ] else [ b ]`, so `b block_len 0 > and_then [ b 0 block_get x = ]` guards the access that `b block_len 0 > b 0 block_get x = and` would perform even on an empty Block (`and` and `or` evaluate both sides). Before v1.62, `when` and `unless` were these value forms (`unless` was b when a is 0, else 0).
- `select` chooses a value with no branching: `vt vf flag select` -> vt if flag nonzero else vf. Both operands are always evaluated.
- Counted loops:
    `n [times| i | body ]`         body runs n times, i = 0, 1, ..., n-1
    `lo hi [for| i | body ]`       body runs for i = lo, lo+1, ..., hi-1 (half-open)
  n, lo and hi are Ints taken off the stack (a Float or a Scalar is a TypeError; a value of unknown kind that is not an integer stops the program); zero iterations when n <= 0 or hi <= lo. The body sees `i` (an Int) and every name in scope. Its net effect MUST be 0, but it may consume values below it and push replacements, which is how accumulators are threaded: `0 10 [times| i | i + ]` leaves 45, `1 1 11 [for| i | i * ]` leaves 10 factorial, `0 1 20 [times| i | swap over + ] drop` leaves fib(20). Loops nest, and an inner body sees the outer index. A loop compiles to a C `for` loop inside the enclosing word, with the values the body reaches below its entry kept in C locals: no call per iteration and no 65,536 limit. There is no `break`: for an early exit, write a self-recursive word.
- Early exit (as Common Lisp's loop): `until [ c ]` or `while [ c ]` as the FIRST thing in a times/for body. Before each trip c runs; `until` ends the loop when c is true, `while` when c is false. c must leave exactly one flag; it sees the index and every name in scope, and it may read a value the loop carries (`0 100 [times| i | until [ dup 20 > ] i + ]` stops once the sum passes 20). The loop then leaves what it carries, exactly as when it runs out. Anywhere else `until` and `while` are a ParseError.
- Search: `n [find| i | c ]` leaves the first i in 0..n-1 for which c is true, or -1 when there is none, and stops there (`10 [find| i | i i * 30 > ]` is 6). c must leave exactly one flag and may not take values off the stack below it (read names instead).
- Other loops are tail-recursive words. A word's call to itself in terminal position is a jump (each trip rebinds the word's entry frame, and frames bound in the body are released before the jump, so a long-running tail-recursive word keeps no memory per trip). Since v1.81 words that call each other in terminal position (A's last call is B, B's last call is A, or a longer cycle) are a loop too: each word of the cycle is compiled with the others' bodies in place of those calls, so every trip ends in its own call to itself. This needs every word of the cycle to take its state as inputs; a cycle through a word without inputs still nests one call per trip, is bounded at 65536 nested calls (MAX_FRAMES; exceeding it stops the program with `Fatal: Max frames exceeded`), and draws `WARNING MutualRecursion` (on stderr after `ACCEPT`). A cycle through a non-terminal call (bounded recursion such as a tree walk) is ordinary recursion and is not reported.
- Iterators over a Block:
    `[map|  idx val ctx | body ]`          body effect: ( idx val -- val' )
    `[fold| idx acc val ctx | body from init ]`  body effect: ( idx acc val -- acc' )
  `from init` sets the initial accumulator: any expression that leaves exactly one value (`from 0`, `from nil`, `from acc`, `from 1 n +`); the fold's result has its type. Use `_` for an unused ctx. If ctx IS used, push it BEFORE the block: `ctx block [fold| ... ]` (loop pops block first, ctx second).

═══ 4. Data Structures & Access Protocol ═══
A Block is an index-typed anonymous record: an ordered set of typed slots.
- STRUCTURALLY IMMUTABLE, value-mutable: you may replace a slot's value with a value of the SAME type. You may NOT change the shape (slot count) or a slot's type. Changing a slot's type is rejected by the checker.
- Homogeneous Block (all slots same type) = array/vector.
- Heterogeneous Block (mixed slot types) = record.

Access has one spelling (v1.83; the aliases `at`, `array_at`, `arr_at`, `list_at`, `block_at`, `array_get`, `list_get`, `record_get`, `array_set`, `list_set` and `record_set` are gone):
    `b i block_get`      ( b:Block i:Int -- v )     element i
    `b i v block_set`    ( b:Block i:Int v -- b2 )  functional update: arity (3, 1), net effect -2

- `block_set` (on any Block: an array, a list, a string) is a FUNCTIONAL update, not an in-place mutation: it copies the collection, writes the one slot, and returns the new value. The original value is unchanged and remains valid to use. Heap cells are different: `hwrite`, and a `#record`'s field setters (§5), write the cell in place and return nothing; the cell then owns the value stored. Never change a slot's shape or type (see §10).
- The library's collections use the same shape with their own names: `vec_get`/`vec_set`, `dict_get`/`dict_set`, `floats_get`/`floats_set`, a record's `Name_field`/`Name_field_set`.

═══ 5. Heap & Memory Protocol ═══
- `size hnew -> ptr` allocate cells. Every cell starts as the integer 0 and holds one value of any kind; each takes 16 bytes. `ptr idx hread -> val`. `ptr idx val hwrite`.
- Argument order: a word that stores into, adds to or writes to something takes that thing first, then any index or range, and the value last: `p i v hwrite`, `p start count v hfill`, `b x cons`, `fh ch fputc`, `fh str fwrite`, `fh a start count bytes_write`, `a i x floats_set`, `v x vec_push`, `d k v dict_set`, and a record's setters. There is no word that takes the value first.
- Ptr is opaque: `ptr 1 +` is a static `TypeError`. Compute the offset as an Int, then pass it: `ptr offset hread`.
- Block access (`block_get`) and heap access (`hread`) are different: `block_get` indexes a Block value; `hread` reads a heap Ptr. They are NOT interchangeable.
- Limits: the number of live allocations is limited only by memory (the allocation table grows), and an allocation may hold any number of cells. `hmark`/`hrelease` still matter: memory that is never released stays allocated.
- Ownership: a Block holds a reference to each Block inside it and releases them when it is freed, so nested Blocks (rows of values, pairs, a Block of strings) cost nothing once the outer Block is gone. A heap cell likewise owns what it holds (overwriting or `hrelease` releases it).
- In-place swap: read BOTH cells before writing EITHER, or the first write overwrites the value the second needs.
- Bulk cells: `hmove` ( src:Ptr soff:Int dst:Ptr doff:Int count:Int -- ) copies count cells from src to dst, overlapping ranges of one allocation included (as memmove); `hfill` ( p:Ptr start:Int count:Int v:Unknown -- ) stores v in every cell of the range. Both check their ranges against the allocations; a range outside one is a fatal error.
- `hmark ( -- mark:Int )` / `hrelease ( mark:Int -- )`: bound heap growth. `hrelease` frees every heap cell allocated since the matching `hmark` and rewinds the allocator. Any `Ptr` obtained between the `hmark` and its `hrelease` is invalid afterward: using it (`hread`, `hwrite`, the bulk heap words) is a fatal error that says so, even after its slot has been reused by a newer allocation (each Ptr carries its allocation's generation). The message names where the allocation was made (the word and line, and the user word that called a library word such as `vec_new`) and which `hrelease` released it.
- `region [ body ]` (v1.82) is `hmark`, the body, and the matching `hrelease`, as one statement: everything the body allocates is released when it ends. The body's net effect MUST be 0 (nothing made in it can be left). The checker rejects storing a value allocated inside a region into a container that existed before the region began (`RegionEscape`): an `hwrite` or `hfill` into an outer Ptr, an outer record's setter, `vec_push`/`vec_set`/`dict_set` on an outer collection, and the list, map, array and record lexicons' setters. A value counts as allocated in the region when it comes from an allocating word (`hnew`, `bytes_new`/`ints_new`/`floats_new`, a record's `_new`, `vec_new`, `dict_new`, ...) or from a word of the program that returns one. Escapes the checker cannot see are still caught at run time.
- Typed-heap-wrapper idiom: `hread` is typed `Unknown`, so raw heap access is a type-erasure boundary. Confine that erasure to a handful of named wrapper words whose declared signature states the real result type, which the checker trusts at the call site instead of re-deriving it:
  ```scrooge
  #row_at ( tbl:Ptr idx:Int -- row:Block )
    tbl idx hread
  end
  ```
  This is an unchecked assertion, exactly like any other signature: if the heap cell does not actually hold a `Block`, downstream code type-checks against a lie. Prefer this over spreading bare `hread` calls across the program.
- Records: `#record` names a heap layout and generates its typed wrappers, so offsets are never hand-assigned. Each field is `name Type count init`: Type is one of the §2 type tags, a declared type (`#type`, `#enum`) or a record; count is a positive integer; init is the value every cell of the field starts with, one token: a number, a string, `nil`, `hnull`, an enum member or a word that takes nothing and leaves one value (`mkvec`). `nil` is the empty Block, so it initialises only a Block field; a compact array, Vec or Dict field is made by a word: `#mk_w ( -- a:Floats ) 0 floats_new end`, then `w Floats 1 mk_w`. The initial value is required and is checked against the field's type:
  ```scrooge
  #record State
    grid Int 81 0
    rowm Int 9  -1
    kids Block  1  nil
    next State  1  hnull
  end
  ```
  A record is its own type, a Ptr at run time (like `#type State Ptr`). It generates ordinary words: `State_size ( -- n:Int )` (92), `State_new ( -- s:State )`, which allocates the cells and stores each field's initial value, and per field a getter and a setter. The setter takes the record first and the value last, as the library's words do: `State_grid ( s:State i:Int -- v:Int )` and `State_grid_set ( s:State i:Int v:Int -- )`. A count-1 field has no index: `State_kids ( s:State -- v:Block )`, `State_kids_set ( s:State v:Block -- )`. A field of a record type holds that record or `hnull`; compare it with `hnull =`. Every field also gets `State_grid_off ( -- n:Int )`, the cell where it starts (0 for grid, 81 for rowm, 90 for kids), for the words that take a raw offset; they take the Ptr, which `State_raw` gives: `s State_raw :p State_rowm_off :start 9 :count 0 :v hfill` (clear rowm), `hmove`, `hsort`, `fread_into`. `State_of ( x:Ptr -- s:State )` turns a Ptr back into a State; both cost nothing. A State passed where a Ptr or another record is expected is a TypeError. Fields are laid out in order (grid at cells 0-80, rowm at 81-89, kids at 90, next at 91), so they cannot overlap. An index is not checked against the field's count (only against the whole allocation, as for any `hread`). A word named `record` is still an ordinary definition: `#record (` starts a signature, `#record Name` a declaration.
- Distinct types and enums: `#type Name Base end` declares a type that is a Base (Int, Float, Ptr, Block or File) at run time but its own type to the checker; `#enum Name member ... end` declares one whose values are the named codes 0, 1, ... in order. Both are erased: no cost at run time. A type name starts with a capital letter. They are used as tags like any other, in signatures, record fields and word parameters:
  ```scrooge
  #enum Kw select from where union end
  #record Tk kind Kw 1 Kw_select val Int 1 0 end
  #is_union ( t:Tk -- f:Int ) t Tk_kind Kw_union = end
  ```
  `#type Name Base` generates `Name_of ( x:Base -- v:Name )` and `Name_raw ( v:Name -- x:Base )`. `#enum Name` generates those (with Base Int), one word per member, `Name_select ( -- v:Name )` (0 here), `Name_count ( -- n:Int )` (4) and `Name_name ( v:Name -- s:Block )` (`Kw_union Kw_name` is `"union"`). An enum's `Name_of` stops the program (`abort`) on a number that is not one of its codes. The checker treats a distinct value as different from every other type, except `Unknown`:
  - `=`, `!=`, `<`, `>`, `min` and `max` take two values of the same distinct type (`min`/`max` keep the type). A distinct value against another known type is a `TypeError`: `t Tk_val Kw_union =` compares an Int with a Kw.
  - Any other use needs the base type: `k 1 +`, `k print_int` and a Kw passed for an `Int` parameter are `TypeError`s; write `k Kw_raw`. An Int passed for a `Kw` parameter is one too; write a member or `n Kw_of`.
  - A word whose result is declared a distinct type must leave one, and a word whose result is declared another type must not leave a distinct value: `#d ( -- k:Kw ) 118 end` is a `TypeError`. Only `Name_of` and `Name_raw` convert.
  - What comes back from `hread`, `block_get` and the like is `Unknown` and is accepted anywhere; store distinct values in record fields declared with the type to keep the check.
  A library lexicon can declare types too (§8). A word named `type` or `enum` is still an ordinary definition (`#type (`).
- Records as values: `#struct Name field Type ... end` declares an immutable value of its own type, a Block of its fields at run time (`#record` is the mutable heap layout). It generates `Name_make` ( f1:T1 ... fn:Tn -- v:Name ), whose inputs are the field names, so a call can be labelled (`1 :x 2 :y Pt_make`); per field a getter `Name_f` ( s:Name -- f:T ) and an update `Name_with_f` ( s:Name f:T -- s:Name ) that returns a new value, leaving the old one as it was; and `Name_of` / `Name_raw` as for `#type`. Two values of one struct type compare with `=` field by field, sort (`hsort`, `vec_sort`, `sort_cmp`) field by field in declaration order, and are written whole by `to_str`. A field type is any type tag, including another struct, an enum or a compact array. A field name must not make a generated name twice (`x` beside `with_x`). `#struct (` is still a word named struct.

═══ 6. Bracketed Values Are Data ═══
- A `[ ... ]` written as a value (anything that is not a cond branch, a when/unless/region body, a loop or a map/fold) is a DATA literal: it may contain only literals (numbers, strings, `nil`) and other such `[ ... ]`, nested to any depth: `[ 1 [ 2 3 ] "ab" nil ]` is valid. Anything else inside it (a word, a variable, a binding, a cond) is a ParseError, with or without nesting: `-> [ x y ] [ x y ]` is rejected. Build a Block from computed values with `cons` or `pair` (or `block_set` on a literal of the right shape).
- Cond branches, frame bodies and map/fold bodies are code, not values, and nest freely to any depth. Moving an inner loop or conditional into a named helper word is good style (it names the step and keeps each word short), not a rule.

═══ 7. Primitives ═══
- Explicit Float Cast: `to_float` ( x:Scalar -- f:Float ).
- Absolute Value: `abs` ( a -- b ), of the same kind. Min/Max: `min`, `max` ( a b -- c ), two numbers of one kind, giving that kind.
- Real functions: `exp`, `log`, `sqrt` ( x:Scalar -- y:Float ) and `pow` ( x:Scalar y:Scalar -- z:Float ), x to the power y. They take Ints or Floats and always return a Float, with C's results at the edges: "0 log" is -inf, "-1 sqrt" and "-1 log" are nan, a large "exp" is inf (print_float prints these as inf, -inf, nan or -nan). `floor` ( x:Scalar -- n:Int ) is the largest integer not above x, as an integer ("-2.5 floor" is -3; an integer passes through; NaN, infinity or a float outside the 64-bit range is fatal, as for to_int).
- Random numbers: `rand` ( -- x:Float ) is a pseudo-random float, uniform on [0, 1), with 53 random bits (xorshift64*). `seed` ( s:Int -- ) restarts the sequence from the integer s; every seed, 0 included, gives a different sequence. A program that never calls seed gets the sequence of "0 seed", so a run is reproducible unless the program seeds from something that varies (for example clock_ns). An integer in 0..n-1: "rand n to_float * to_int".
- Stack Shufflers: `dup` ( x -- x x ) | `drop` ( x -- ) | `swap` ( x y -- y x ) | `rot` ( x y z -- y z x ) | `over` ( x y -- x y x ).
- Block Build: `cons` ( block x -- block' ), x in front | `pair` ( a b -- [a b] ) | `nil` ( -- [] ) | `block_len` ( block -- n ). | `block_slice` ( b:Block start:Int count:Int -- b2:Block ), the count elements from index start as a new Block (a range is a start and a count everywhere, v1.83); the range clamps to the Block, and a count <= 0 gives an empty Block. O(count).
- Math: `+`, `-`, `*` | `/` | `\` (remainder). The operand pushed first is the left one: "a b -" is a - b, "a b /" is a / b, "a b \" is a mod b, whatever computed a and b. In a long expression, check which value is below which: "w lr v * -" is w - lr*v, but "lr v * w -" is lr*v - w, and both are accepted. With two integers, `/` rounds DOWN (floor; since v1.83) and `\` is the matching floored remainder, with the sign of the divisor ("-7 2 /" is -4 and "-7 2 \" is 1; "7 -2 /" is -4 and "7 -2 \" is -1), so a = b*(a/b) + a\b for every sign. C, and SQL engines such as SQLite, truncate instead (-7/2 is -3): write that as a word if you need it. With a float operand, `/` divides as floats; `\` needs integers. Division or remainder by 0 is a fatal error. Integer `+`, `-`, `*` wrap around on overflow (two's complement, 64-bit). An operand that is not a number (a Block, a Ptr) is a fatal error at run time.
- Bitwise (integer operands only): `bitand`, `bitor`, `bitxor`, `bitshl`, `bitshr` ( a:Int b:Int -- c:Int ). "x n bitshl" and "x n bitshr" shift the 64-bit pattern; `bitshr` is LOGICAL (zero-filling: "-8 1 bitshr" is 9223372036854775804; use `/` for an arithmetic shift). A count of 64 or more gives 0; a negative count is a fatal error (it is always a bug, e.g. "1 d 1 - bitshl" with d=0) | `bitnot` ( Scalar -- Scalar ) | `bitcount`, `bitctz`, `bitclz` ( Scalar -- Scalar ): the number of set bits, trailing zero bits and leading zero bits of the 64-bit pattern (a negative number has bit 63 set); `bitctz` and `bitclz` of 0 are 64.
- Compare: `=`, `!=`, `>`, `<`, `>=`, `<=` (the last two primitives since v1.84), each giving an Int flag. Two numbers compared are of one kind (`x 0.0 >` for a Float x); `=` and `!=` also compare Blocks and Ptrs. `<` and `>` compare numbers; an operand that is not a number is a fatal error at run time. To order Blocks, use `sort_cmp` ( a:Unknown b:Unknown -- c:Int ): -1, 0 or 1 in `hsort`'s order (element by element, a shorter Block first when it is a prefix of the other, numbers before Blocks), so two strings compare in byte order ("\"ab\" \"b\" sort_cmp" is -1). `=` and `!=` accept any two values: numbers compare by value (an integer equals a float of the same value), Blocks element by element (the same length and every pair of elements equal, recursively; a string is a Block, so this compares strings), Ptrs by identity (the same allocation), and values of different kinds are unequal. `>` and `<` compare numbers.
- Logic: `and`, `or` ( a:Int b:Int -- c:Int ) (eager, both operands evaluated) | `not` ( a:Int -- b:Int ) (1 if a is 0).
- I/O: `print_char` ( ascii -- ) | `print_int` ( n:Int -- ) (a Float is a TypeError: convert it with to_int or floor, or use print_float) | `print_float` ( x:Scalar decimals:Int -- ), a number with 0 to 17 decimals, formatted as C's printf %.*f (so -0.5 with 0 decimals prints -0). Fixed-point and zero-padded integers: print_fixed and int_to_str_pad in the strings lexicon.
- Files: `fopen` ( path:Block mode:Int -- fh:File ok:Int ) | `fclose` ( fh:File -- ok:Int ) | `fgetc` ( fh:File -- ch:Int ok:Int ) | `fputc` ( fh:File ch:Int -- ok:Int ) | `fread` ( fh:File n:Int -- str:Block ) | `fwrite` ( fh:File str:Block -- written:Int ) | `freadline` ( fh:File -- line:Block got:Int ) | `freadline_into` ( fh:File a:Bytes -- n:Int ), the next line into a from index 0 (newline consumed, not stored): its length, or -1 at the end of input; no Block per line, and a line longer than a is fatal (v1.84) | `fread_into` ( fh:File p:Ptr start:Int count:Int -- got:Int ) | `fwrite_from` ( fh:File p:Ptr start:Int count:Int -- written:Int ), the mirror of fread_into: the cells p[start..start+count) written as bytes in one call (each must hold an integer 0-255, else a fatal error) | `fflush` ( fh:File -- ok:Int ), writes out what is buffered for fh now (stdout is block-buffered when it is redirected to a file, so a long run's progress lines appear only when the buffer fills or the program ends, unless flushed; stderr is unbuffered) | `fseek` ( fh:File pos:Int -- ok:Int ) | `ftell` ( fh:File -- pos:Int ). See §12.
- Command line and environment: `argc` ( -- n:Int ) | `argv` ( i:Int -- arg:Block ok:Int ) | `getenv` ( name:Block -- value:Block ok:Int ), read-only. See §13.
- Clock: `clock_ns` ( -- ns:Int ), nanoseconds from a monotonic clock. The epoch is arbitrary, so only the difference of two readings means anything: read it before and after the work and subtract.
- Heap Arena: `hmark` ( -- mark:Int ) | `hrelease` ( mark:Int -- ) | `hsort` ( p:Ptr start:Int count:Int -- ): sorts the cells start to start+count-1 ascending, in place, stably. Numbers are ordered as `<` orders them; a Block is ordered element by element (a shorter Block first when it is a prefix of the other), so strings sort in byte order and rows column by column; every number sorts before every Block. A cell holding a Ptr (at any depth), or a range outside the allocation, is a fatal error. The util lexicon's block_sort uses the same order. See §5.
- Runtime errors: a fatal error at run time (an out-of-range `hread`, "Modulo requires integers", "Max frames exceeded", ...) prints `Fatal: ...` and then the words that were running, innermost first, each as "in #word (defined line N)" ("strings.sg line N" for a library word), ending "in top level"; the program exits with status 70 (EX_SOFTWARE), so a fault is told apart from a program's own error stop (`abort`, or `exit` with 1: status 1). A word that calls no other word is not tracked, so a fault inside one is shown in its caller.
- Debugging: `trace` ( v:Unknown -- ) prints the line "trace line N: " and then the value to stderr (after flushing stdout), for a value of any type: a Block shows its first 64 elements, and as text when every element is a printable character; a Ptr shows its size. N is the line of the `trace` in the program's own file. For invariants, the util lexicon has an assert word, ( ok:Int msg:Block -- ), which aborts with msg when ok is 0 (§8).
- Text of any value: `to_str` ( v:Unknown -- s:Block ) is the value written out as a string. Integers are written in decimal and floats so that they read back exactly and never look like integers (3.0). A Block is written as "[ 1 [ 2 3 ] ]", with every element. A Block of printable characters also carries its text as a comment, "[ 104 105 ] { \"hi\" }", so a string inside a row reads as one element. A Ptr is written as "Ptr#3(10 cells)". Use it for messages and tests: "x to_str str_print".
- Compact arrays: Bytes, Ints and Floats are heap arrays of raw elements (1, 8 and 8 bytes each, against 16 for a Ptr's value cells), types of their own to the checker and Ptrs at run time, released by `hrelease` like any allocation. The array comes first. `bytes_new` / `ints_new` / `floats_new` ( n:Int -- a ) make one, all zeros; `bytes_len` / `ints_len` / `floats_len` ( a -- n:Int ); `bytes_get` / `ints_get` ( a i:Int -- x:Int ) and `floats_get` ( a i:Int -- x:Float ); `bytes_set` / `ints_set` ( a i:Int x:Int -- ) and `floats_set` ( a i:Int x:Scalar -- ), an Int converted; `bytes_fill` / `ints_fill` ( a start:Int count:Int x:Int -- ) and `floats_fill` ( a start:Int count:Int x:Scalar -- ); `bytes_move` / `ints_move` / `floats_move` ( src soff:Int dst doff:Int count:Int -- ), overlap-safe. `bytes_read` ( fh:File a start count -- got:Int ) and `bytes_write` ( fh:File a start count -- written:Int ) stream a file; `bytes_to_block` ( a start count -- s:Block ) and `bytes_from_block` ( s:Block -- a ) convert strings; `ints_sort` / `floats_sort` ( a start count -- ) sort a range ascending. An index outside 0 .. len-1, a range past the end, a byte outside 0..255 or a float stored in an Ints stops the program with the word's name; hread and hwrite on a compact array stop too, and are TypeErrors when its type is known.
- Kernels over compact arrays (v1.77), in C and vectorised: `floats_dot` ( a ao b bo n -- s ), `floats_axpy` ( y yo x xo n g -- ) (y += g*x), `floats_add` ( y yo x xo n -- ) (y += x), `floats_mul` ( y yo x xo n -- ) (y *= x), `floats_scale` ( a start count g -- ), `floats_sum` / `floats_max` ( a start count -- x:Float ) and `floats_argmax` ( a start count -- i:Int ), `floats_from_bytes` ( y yo b bo n scale -- ) (y = b * scale), `ints_sum` / `ints_max` / `ints_argmax` ( a start count -- n:Int ); every start, count and offset is an Int, and `floats_dot` gives a Float; and `bytes_be32` / `bytes_le32` and `bytes_be16` / `bytes_le16` ( a i -- n ), all unsigned (since v1.87 for the 32-bit ones: 0 .. 4294967295), to read binary headers. Every range is checked; an argmax or max of an empty range stops the program. A kernel is several times faster than the same loop written in Scrooge: write the inner loops of numeric code with them.
- Numbers and types: `to_int` ( x:Scalar -- n:Int ) truncates a float toward zero (an integer passes through; NaN, infinity or a float outside the 64-bit range is fatal); `float_to_str` ( x:Scalar decimals:Int -- s:Block ) is the text print_float would print (0-17 decimals); `type_of` ( v:Unknown -- t:Int ) is 0 for an integer, 1 a float, 2 a Block, 3 a Ptr (a File handle is an integer); `str_to_float` ( chars:Block start:Int count:Int -- x:Float ok:Int ) reads the decimal number in that range (digits, sign, point, exponent and nothing else) as x and 1, or 0.0 and 0 (v1.84).
- `hnull` ( -- p:Ptr ) is a Ptr that refers to nothing, for an absent link in a heap structure: it equals only another hnull (test with "p hnull ="), and hread/hwrite through it are fatal.
- Exit: `exit` ( code:Int -- ) ends the program with that status (0-255), flushing stdout first; like `abort` it never returns, so a cond branch ending in it is exempt from branch matching.
- Abort: `abort` ( Block -- ), never returns. Prints its Block argument to stderr as characters and terminates the process with exit status 1. A cond branch whose terminal call is `abort`, `exit`, or a word of the program whose body always ends in one of them (a "die" helper) is exempt from the "branches MUST match in count and type" rule (§10): the checker unifies on the OTHER branch's stack effect/type instead, since the aborting branch never produces a value.

═══ 9. Track 2 Static Verification & Error Classes ═══
A name has one meaning in a body, so three errors reject a name that would have two: `AliasRebindsOuter`, a frame inside a loop or map/fold body that binds a name already bound outside it (§2 Scope; it would be a new name for one iteration, and the outer one would never change: carry the value on the stack below the loop instead), `AliasShadowsWord`, a frame alias spelled like one of the program's own words (until the end of the block the name would be the value, and the word could not be called), and `ParamNamedLikeWord`, an input named like a word that the body calls (the name would be the call, not the input); rename the alias or the input. Warnings (on stderr after ACCEPT, never a rejection): `MutualRecursion` for a loop written as a cycle of tail calls (§3), `LargeWord` for a word over 60 tokens or with more than 3 nested conds and loops (§2 Small words), `UnusedWordTemplate` for a word with word parameters that is never called (§2 Word parameters), and `AllocInLoop` (since v1.91) for a word called on every trip of a loop (a times/for/find loop, a map or fold, or a word that calls itself) that allocates heap memory (`hnew`, `bytes_new`, `ints_new`, `floats_new`, a record's `_new`, `vec_new`, `dict_new`, ...) nothing frees, with the chain of calls that reaches the allocation: allocate once before the loop, or put `region [ ]` around one trip's work (§5). An ArityMismatch names the call where the stack runs out, with the inputs it takes, the values it found (named when they come from the word's inputs) and the deepest inputs, which are the missing ones: "The stack runs out at `pa` (line 6), which takes 3 values ( label:Block v:Int n:Int ) and finds 2 ( v:Int n:Int ): the missing one is the deepest, ( label:Block )"; top-level code is checked the same way from an empty stack, so a top-level call with too few arguments is rejected rather than stopping the program with `Fatal: Stack underflow`. When a body leaves more values than its signature gives, the message lists the values left with the line that pushed each: "At the end the stack holds ( z:Z from line 9, Scalar from line 10 ) and the signature gives ( b:Int ): 1 of these is left over" (here a field word took the field's record, not `z`).
A REJECT lists every error found, in source order, and the compiler exits with status 1 (ACCEPT: 0); a build that is rejected removes any earlier binary at the output path, so a stale program is never left to be run by mistake. Words with a stack-effect error are not type-checked, but every other word is, in the same run.
Static checker enforces:
- `ArityMismatch`: Signature vs body net effect mismatch, signature vs frame input count mismatch, or unequal cond branches.
- `ArgumentLabel`: A label naming a parameter other than the one its value is passed as, or a call with --labels-required or more inputs (default 4) whose arguments are not all labelled or passed by matching names (§2).
- `TypeError`: A distinct type (`#type`, `#enum`, §5) used as another type, compared with another type, or left as a result declared another type; tagged parameter call-site type mismatch (one error per call: each parameter that does not match, by name, then what the callee takes and what the top of the stack holds, deepest first, and, when the same kinds of values are there in another order, "check the order of the arguments"), `block_get` indexing into a `Ptr`, a number or a `File`, an Int and a Float in one operation, a Float or Scalar where an Int is taken or the reverse (§1 Numbers), or a signature declaring an unrecognized type tag (§2).
- `UnknownWordError`: Invocation of an undeclared word or primitive, in a word body or in top-level code. When a library lexicon defines the word, the message names it and the `use` line to add.
- `ParseError`: Unterminated brackets, missing signature parentheses, a `[ ... ]` value containing code (§6), a frame with no `[ names ]` after `->`, a malformed `cond`, a stray `?`/`else` that no `cond` claims, an `end` outside any definition, or a definition with no `end`. Cond-related ParseErrors report `line L col C` and name the cond they concern.
- `ReservedWordIdentifierError`: Reserved word used as a parameter name (an input whose name is a primitive or a reserved word and which the body mentions, since that mention is the primitive), a frame alias, or the name of a `#word` definition (when it is not a primitive; see `DuplicateWordError`).
- `DuplicateWordError`: Local `#word` definition shadowing a builtin primitive, a `use`-imported lexicon word (the message names the lexicon), or a duplicate local word definition.

═══ 10. Hard Rules (violations are rejected) ═══
- Reserved words — never use as parameter name or frame alias: use lexicon from and or not cond else map fold select nil cons pair end dup drop swap rot over block_len seed rand exp log pow sqrt floor abs max min to_float bitand bitor bitxor bitshl bitshr bitnot hnew hread hwrite print_char print_int abort hmark hrelease fopen fclose fgetc fputc fread fwrite argc argv clock_ns block_slice bitcount bitctz bitclz hsort print_float getenv freadline fread_into fseek ftell trace hmove hfill exit to_int float_to_str type_of hnull when unless and_then or_else sort_cmp fwrite_from fflush to_str bytes_new bytes_len bytes_get bytes_set bytes_fill bytes_move ints_new ints_len ints_get ints_set ints_fill ints_move floats_new floats_len floats_get floats_set floats_fill floats_move bytes_read bytes_write bytes_to_block bytes_from_block ints_sort floats_sort floats_dot floats_axpy floats_add floats_mul floats_scale floats_sum floats_max floats_argmax floats_from_bytes ints_sum ints_max ints_argmax bytes_be32 bytes_le32 bytes_be16 bytes_le16 until while region str_to_float freadline_into.
- Never shadow your own word names or imported lexicon words with a local definition or alias.
- `cond` condition expression MUST NOT be enclosed in brackets `[ ... ]`.
- `cond` branches MUST match in count and type, except when exactly one branch's terminal call is `abort` (or `exit`, or a word that always ends in one of them): that branch is exempt, and the other branch's effect/type is used (§7). An omitted else-branch counts as `[ ]`.
- A `[ ... ]` value contains only literals and other such values (§6).
- `block_get`/`block_set` only on a `Block`; never on a `Ptr` or a number.
- `block_set` may replace a slot's value only with a value of the SAME type — never change shape or type. Enforced by Track 2 wherever both the slot's current type and the incoming value's type are statically known; unchecked when either is `Unknown`.
- Pointers are opaque — no pointer arithmetic (`ptr 1 +`).
- `and`/`or` are eager — guard risky paths with `cond`, not `and`/`or`.

═══ 11. Worked Examples ═══
Fold to a number:
```scrooge
#sum ( block:Block -- total:Int )
  block [fold| idx acc val _ | acc val + from 0 ]
end
```

Map over a block:
```scrooge
#double_all ( block:Block -- doubled:Block )
  block [map| idx val _ | val 2 * ]
end
```

Fold building a block ('from nil'):
```scrooge
#copy_reverse ( block:Block -- reversed:Block )
  block [fold| idx acc val _ | acc val cons from nil ]
end
```

Tail-recursive loop:
```scrooge
#fact_iter ( n:Int acc:Int -- r:Int )
  n 0 =
  cond [ acc ] else [ n 1 - n acc * fact_iter ] ?
end
#fact ( n:Int -- r:Int )
  n 1 fact_iter
end
```

Float conversion before division:
```scrooge
#avg_calc ( total:Int count:Int -- avg:Float )
  total to_float count to_float /
end
```

Typed-heap-wrapper (confines the `hread` type-erasure boundary to one named word, per §5):
```scrooge
#row_at ( tbl:Ptr idx:Int -- row:Block )
  tbl idx hread
end
```

Abort on an unreachable branch (per §7/§10, the aborting branch is exempt from the cond stack-effect match):
```scrooge
#safe_div ( a:Int b:Int -- r:Int )
  b 0 =
  cond [ [ 68 105 118 32 98 121 32 122 101 114 111 ] abort ] else [ a b / ] ?
end
```

Sequential file I/O, whole-file and character-at-a-time (per §12):
```scrooge
use "file"
#count_lines_loop ( fh:File n:Int -- total:Int )
  fh n fh fgetc
  -> [ fh n ch ok ] ok not
  cond [ n ] else [ fh n ch 10 = + count_lines_loop ] ?
end
#copy_file ( src:Block dst:Block -- ok:Int )
  dst src f_read_file
  -> [ dst text ok ] ok not
  cond [ 0 ] else [ dst text f_write_file ] ?
end
```

Bound heap growth around a unit of work with `region` (per §5):
```scrooge
#process_query ( -- )
  region [
    10 hnew drop
  ]
end
```

═══ 12. File I/O Protocol ═══
- A `File` is an opaque handle, exactly as a `Ptr` is (§5): the checker rejects
  arithmetic on it, `hread`/`hwrite` through it, and `block_get`/`block_set` into
  it. It is produced only by `fopen` and consumed only by the six file
  primitives. The value is not a memory address and carries no length.
- Open: `path mode fopen -> fh ok`. `path` is a Block of character codes (a
  string literal is exactly that). `mode` is 0 read, 1 write (truncating), 2
  append. ok=0 means the open failed -- the file does not exist, permission
  was refused, or every openable handle is already in use -- and `fh` must not
  be used. Prefer `library/file.sg`'s named `f_open_read`/`f_open_write`/
  `f_open_append` over a bare mode integer.
- Close: `fh fclose -> ok`. ok=0 means the handle was already closed, or names
  a standard stream (which this process does not own). Closing flushes.
- Handles 0, 1 and 2 are pre-opened as stdin, stdout and stderr, so the same
  read and write words serve the standard streams; `file.sg` names them
  `f_stdin`/`f_stdout`/`f_stderr`. Output to stdout is buffered: `print_char`,
  `print_int`, `print_float` and writes to handle 1 share one buffer, so they
  stay in order. It is flushed before anything is written to stderr (so an
  error or `abort` message still follows the output before it), before a
  read from stdin (so a prompt is visible), and at exit. A real file stays
  buffered until it is closed or the process exits normally.
- Sequential read, two granularities:
    `fh fgetc -> ch ok`        one character; ok=0 at end of input (ch=0)
    `fh n fread -> str`        up to n characters as a Block; `str block_len` is how
                               many were actually read, and an empty Block
                               means end of input
    `fh freadline -> line got` the next line, in one pass; the newline is
                               consumed, not returned; got=0 only at end of
                               input with nothing read
    `fh p start n fread_into -> got`
                               up to n bytes into heap cells start.. of p, each
                               an integer 0-255; got is how many (0 at end of
                               input). No Block is built, so a large file can
                               be streamed through a fixed heap buffer
  Use `freadline` (or `freadline_into`, into a Bytes) for line-structured text, `fread_into` or
  `fread` for throughput, and `fgetc` only when the read must stop at some
  other delimiter: a Scrooge-level per-character loop pays a word call and a
  `cons` copy per character.
- Sequential write, the same two granularities:
    `fh ch fputc -> ok`        one character; ok=0 on a write error
    `fh str fwrite -> written` every character of str; written < `str block_len`
                               means the write failed part way
- Partiality is always reported through an Int flag or a length, never by
  aborting -- the same convention as `lst_try_push`, `map_set` and
  `str_to_int`. Only an outright protocol violation is fatal: a non-File where
  a File is required, a closed handle, a non-Block path, a negative `fread`
  count, a negative `fseek` position, or a `fread_into` range outside the
  allocation. This mirrors `hread`/`hwrite`.
- Position: `fh pos fseek -> ok` moves to an absolute byte offset (ok=0 when
  the stream cannot seek, e.g. a pipe; a negative pos is fatal);
  `fh ftell -> pos` is the current offset, -1 when the stream has none.
- Cost model: a file read into a Block costs one Block slot per character, and
  a Block slot is considerably wider than a byte. `f_read_all` materializes an
  entire file that way, which is the right thing for configuration and data
  files and the wrong thing for something far larger than memory -- stream
  such input with `fread` a chunk at a time instead of accumulating it.
- The number of simultaneously open handles is fixed and small (61 beyond the
  three standard streams). Close what you open; exhaustion surfaces as
  `fopen`'s ok=0, not as a crash.

═══ 13. Command-Line Arguments ═══
- `argc ( -- n:Int )` is the number of command-line arguments, and
  `argv ( i:Int -- arg:Block ok:Int )` is the i-th one as a Block of
  character codes. A string literal is exactly such a Block, so an argument
  compares and prints like any other string.
- **The indexing is C's, exactly.** `0 argv` is the program as invoked; the
  first real argument is `1 argv`; `argc` counts both, so it is 1 for a
  program run with no arguments. Nothing is re-based: an index means the same
  thing here as in the `argc`/`argv` of the process itself.
- ok=0 means there is no argument at that index (and the Block is empty). That
  is the ordinary way to ask "was this argument supplied?", so it is a flag
  rather than an abort, exactly as with `fopen`/`fgetc` (§12). A negative index
  is likewise ok=0, not an error. An argument that was supplied but is empty --
  `prog ""` -- returns an empty Block with **ok=1**: present and empty is not
  the same as absent.
- Only a non-integer index is fatal, matching `hread`/`fread`.
- Nothing is materialized up front. A program that never asks pays nothing;
  one that asks for argument 3 allocates that one string. `library/args.sg`'s
  `arg_tail` is the word that deliberately materializes all of them.
- Arguments are read-only. There is no way to alter them.
- The environment is readable, not writable: `getenv` ( name:Block --
  value:Block ok:Int ) has argv's shape, ok=0 and an empty Block for an
  unset variable, ok=1 and the value (possibly empty) for a set one.
  `library/file.sg`'s `f_expand_home` turns a leading `~/`, or a lone `~`,
  into $HOME, leaving any other path unchanged.
- `library/args.sg` (§8) adds the words worth having on top: `arg_prog`,
  `arg_or` (a total accessor taking a default, so no flag reaches the call
  site), `arg_tail` (the arguments without the program name, as a Block of
  Blocks, for `[fold| ... ]`), and `arg_find` (the C index of the first
  argument equal to a given string -- flag scanning), plus flag parsing:
  `arg_flag` (was the flag given), `arg_value_or` (the argument after the
  flag, or a default when it is absent or last) and `arg_int_or` (that value
  as an integer, or a default when absent or not an integer).

Worked example -- greet each argument, or the world if there are none:
```scrooge
use "args"
use "strings"
#greet_step ( idx:Int acc:Int val:Block ctx:Int -- acc2:Int )
  "Hello, " str_print val str_print 10 print_char acc
end
#main ( -- )
  arg_tail -> [ args ] args block_len 0 =
  cond [ "Hello, world" str_print 10 print_char ] else [
    args [fold| idx acc val _ | idx acc val 0 :ctx greet_step from 0 ] drop
  ] ?
end
main
```
