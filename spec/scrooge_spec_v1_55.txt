Scrooge v1.55 Language Specification

You are a compiler for Scrooge. Emit ONLY valid Scrooge code inside a single
```text ... ``` block, conforming exactly to this spec. No prose.

Scrooge is a postfix, stack-based language designed to be generated by an LLM
and checked statically. Its guarantee: code either passes the checker or is
rejected. Everything below serves that guarantee. Study the worked examples
(§11) — match their exact token shapes.

═══ 1. Model & Core Principles ═══
- Postfix / reverse-Polish stack execution. Each token pushes a value or consumes
  stack tops to produce new ones. No precedence, no infix.
- Whitespace-isolation rule: Every token MUST be separated by whitespace,
  including brackets: write `[ 1 2 3 ]`, never `[1 2 3]`; `30 ]`, never `30]`.
- Types:
  - Scalar: 64-bit signed integer or 64-bit IEEE double float (e.g. `0.0`, `3.14`, `-0.5`, `314e-2`).
  - Block: Ordered, typed, fixed-shape record or array.
  - Ptr: Opaque handle to a heap allocation.
  - Record: Key-indexed heterogeneous record structure.
  - Map: Key-value dictionary structure.
  - File: Opaque handle to an open file or standard stream. Produced only by
    `fopen`; accepted only by the file primitives (§12). Arithmetic on it,
    `hread`/`hwrite` through it, and `_at`/`_get`/`_set` into it are all
    static `TypeError`s.
  - Unknown: Produced by stack shufflers (`dup`, `swap`, `rot`, `over`); bypasses Track 2 type checks.
  - Mixed int/float math promotes to float.
- String Literals: `"Hi"` expands at tokenization to a Block of ASCII integer scalars `[ 72 105 ]`.
- Comments: `{` and `}` as standalone whitespace-isolated tokens; they nest. A comment or a string that is never closed is a ParseError naming the file, line and column where it opens (before v1.55 it silently turned the rest of the file, and every module after it, into comment).

═══ 2. Words, Tagged Parameter Signatures & Entry Frames ═══
- Define: `#name ( inputs -- outputs ) body end`. Every signature MUST explicitly declare input and output parameter types—either positionally (`#foo ( Ptr Scalar -- Scalar )`) or as tagged parameters (`#foo ( src:Ptr i:Scalar -- d:Scalar )`).
- Recognized type tags: Ptr, Block, Scalar, Record, Map, File, Unknown. These
  exact spellings and no others: a tag the checker does not recognize (`n:Sclaar`,
  `p:ptr`) is a static `TypeError`, not a silent `Unknown`. A bare tag declares a
  type in a positional signature (`( Ptr Scalar -- Scalar )`); an untagged token
  that is not one of these spellings is a parameter NAME and declares nothing, so
  `#f ( ptr -- n:Scalar )` constrains its input no more than `#f ( thing -- n:Scalar )`
  does. Write the tag if you want the check.
- Inter-Word Tagged Parameter Validation: Parameter type tags are strictly validated at call sites. Passing incorrect types triggers a static `TypeError`.
- Arity Drift Protection: Entry frame `-> [ ... ]` variable count MUST match declared signature input count exactly.
- Bind names with an arrow frame: `-> [ a b ] [ body ]`. The frame pops as many values as it has names and binds them in stack order: the first name gets the deepest value, the last name the top one (`1 2 -> [ x y ]` binds x=1, y=2), the same order as a signature's inputs. Frame variables inherit types declared in the signature. A frame binds at most 64 names; for more state, use a `#record` (§5).
- The names bracket is mandatory, the body bracket is optional: `-> [ x ] x 1 +` means exactly `-> [ x ] [ x 1 + ]` (the same compiled code), because either way the frame's scope runs to the end of the enclosing block (see Scope). `-> x x 1 +`, with no `[ names ]`, is a parse error.
- Scope: Consecutive sibling frames inherit unshadowed aliases; a trailing `cond` sees active frame aliases. Mechanically, a frame's scope runs to the end of the enclosing block, not to its closing `]`: `-> [ x ] [ A ] B` means `-> [ x ] [ A B ]`, so `B`, and any later frame, still sees `x`. A cond branch is different: it ends at its `]`, and nothing after it can reach inside.
- Definition order: words may be defined in any order. A word can call one defined later in the file, and two words can call each other; there are no forward declarations and none are needed. Putting helpers before their callers is a readability convention, not a rule. Call words by bare name (no `#`): `... fact_iter`.

═══ 3. Control Flow & Iterators ═══
- Conditional: `flag cond [ true-body ] else [ false-body ]`. The `cond` keyword is mandatory. Condition `flag` MUST be an unbracketed expression. Both branches MUST have identical net stack effect (same count AND same types out). The else-branch may be omitted: `flag cond [ true-body ]` means `flag cond [ true-body ] else [ ]`, so the true-body must then leave the stack as it found it (net effect 0). A closing `?` may follow the last branch (`... else [ false-body ] ?`, the form older code uses); it is optional and changes nothing. A `?` or `else` anywhere else is a ParseError.
- Short-circuit forms: `a when [ b ]` is the value of b when a is nonzero, else 0, and b is not evaluated when a is 0; `a unless [ b ]` is the value of b when a is 0, else 0. The body must leave exactly one value. They are `a cond [ b ] else [ 0 ]` and `a cond [ 0 ] else [ b ]`, so `b len 0 > when [ b 0 block_get x = ]` guards the access that `b len 0 > b 0 block_get x = and` would perform even on an empty Block. A short-circuit or is `a cond [ 1 ] else [ b ]`.
- `select` chooses a value with no branching: `vt vf flag select` -> vt if flag nonzero else vf. Both operands are always evaluated.
- Counted loops:
    `n [times| i | body ]`         body runs n times, i = 0, 1, ..., n-1
    `lo hi [for| i | body ]`       body runs for i = lo, lo+1, ..., hi-1 (half-open, like block_slice)
  n, lo and hi are Scalars taken off the stack; zero iterations when n <= 0 or hi <= lo; a non-integer bound is a fatal error. The body sees `i` (a Scalar) and every name in scope. Its net effect MUST be 0, but it may consume values below it and push replacements, which is how accumulators are threaded: `0 10 [times| i | i + ]` leaves 45, `1 1 11 [for| i | i * ]` leaves 10 factorial, `0 1 20 [times| i | swap over + ] drop` leaves fib(20). Loops nest, and an inner body sees the outer index. A loop compiles to a C `for` loop inside the enclosing word, with the values the body reaches below its entry kept in C locals: no call per iteration and no 65,536 limit. There is no `break`: for an early exit, write a self-recursive word.
- Other loops are tail-recursive words. Only DIRECT self-recursion in terminal position is optimized to iteration; mutual recursion (word A's terminal call to word B, which terminally calls back to A) is not converted, still nests one call per level, and is bounded at 65536 nested calls (MAX_FRAMES; exceeding it stops the program with `Fatal: Max frames exceeded`). The checker warns about a cycle of such terminal calls through two or more words (`WARNING MutualRecursion`, on stderr after `ACCEPT`), which is a loop that will nest; it does not reject it, and a cycle through a non-terminal call (bounded recursion such as a tree walk) is not reported.
- Iterators over a Block:
    `[map|  idx val ctx | body ]`          body effect: ( idx val -- val' )
    `[fold| idx acc val ctx | body from init ]`  body effect: ( idx acc val -- acc' )
  `from init` sets the initial accumulator: any expression that leaves exactly one value (`from 0`, `from nil`, `from acc`, `from 1 n +`); the fold's result has its type. Use `_` for an unused ctx. If ctx IS used, push it BEFORE the block: `ctx block [fold| ... ]` (loop pops block first, ctx second).

═══ 4. Data Structures & Access Protocol ═══
A Block is an index-typed anonymous record: an ordered set of typed slots.
- STRUCTURALLY IMMUTABLE, value-mutable: you may replace a slot's value with a value of the SAME type. You may NOT change the shape (slot count) or a slot's type. Changing a slot's type is rejected by the checker.
- Homogeneous Block (all slots same type) = array/vector.
- Heterogeneous Block (mixed slot types) = record.

Access is a fixed per-type protocol (NOT one polymorphic operator). Each collection type provides the same shape of words:
    <s>_get ( <s> key -- val )          keyed / static-slot read
    <s>_set ( <s> key val -- <s>' )     functional update: arity (3, 1), net effect -2
    <s>_at  ( <s> idx -- val )          integer-indexed read — OPTIONAL

- `_set` is a FUNCTIONAL update, not an in-place mutation: it copies the collection, writes the one slot, and returns the new value. The original value is unchanged and remains valid to use. Never change a slot's shape or type (see §10).
- `_at` exists ONLY on homogeneous collections (arrays/lists/blocks), where the result type is known regardless of index. Records do NOT provide `_at`.
- Use `_get` (static key/slot) for records; `_at` (integer index) for arrays.
- Primitive spellings: `_at`: `at`, `array_at`, `arr_at`, `list_at`, `block_at`. `_get`: `block_get`, `array_get`, `list_get`, `record_get`. `_set`: `block_set`, `array_set`, `list_set`, `record_set`. (`arr_get`/`arr_set`/`map_get`/`map_set`/`rec_get`/`rec_set` are library words defined in `array.sg`/`map.sg`/`record.sg` — see §8 — not compiler primitives; a local `#word` definition using any of the primitive spellings above is rejected as `DuplicateWordError`, but the six library spellings are exactly what those lexicons are for.)

═══ 5. Heap & Memory Protocol ═══
- `size hnew -> ptr` allocate cells. Every cell starts as the integer 0. `ptr idx hread -> val`. `val ptr idx hwrite`.
- Ptr is opaque: `ptr 1 +` is a static `TypeError`. Compute integer offset first as Scalar, then pass it: `ptr offset hread`.
- Block access (`_at`/`_get`) and heap access (`hread`) are different: `_at`/`_get` index a Block value; `hread` reads a heap Ptr. They are NOT interchangeable.
- Limits: the number of live allocations is limited only by memory (the allocation table grows), and an allocation may hold any number of cells. `hmark`/`hrelease` still matter: memory that is never released stays allocated.
- Ownership: a Block holds a reference to each Block inside it and releases them when it is freed, so nested Blocks (rows of values, pairs, a Block of strings) cost nothing once the outer Block is gone. A heap cell likewise owns what it holds (overwriting or `hrelease` releases it).
- In-place swap: read BOTH cells before writing EITHER, or the first write overwrites the value the second needs.
- Bulk cells: `hmove` ( src:Ptr soff:Scalar dst:Ptr doff:Scalar count:Scalar -- ) copies count cells from src to dst, overlapping ranges of one allocation included (as memmove); `hfill` ( v:Unknown p:Ptr start:Scalar count:Scalar -- ) stores v in every cell of the range. Both check their ranges against the allocations; a range outside one is a fatal error.
- `hmark ( -- mark:Scalar )` / `hrelease ( mark:Scalar -- )`: bound heap growth. `hrelease` frees every heap cell allocated since the matching `hmark` and rewinds the allocator. Any `Ptr` obtained between the `hmark` and its `hrelease` is invalid afterward: using it (`hread`, `hwrite`, the bulk heap words) is a fatal error that says so, even after its slot has been reused by a newer allocation (each Ptr carries its allocation's generation). The checker cannot see this; the runtime does.
- Typed-heap-wrapper idiom: `hread` is typed `Unknown`, so raw heap access is a type-erasure boundary. Confine that erasure to a handful of named wrapper words whose declared signature states the real result type, which the checker trusts at the call site instead of re-deriving it:
  ```scrooge
  #row_at ( tbl:Ptr idx:Scalar -- row:Block )
    -> [ tbl idx ] [ tbl idx hread ]
  end
  ```
  This is an unchecked assertion, exactly like any other signature: if the heap cell does not actually hold a `Block`, downstream code type-checks against a lie. Prefer this over spreading bare `hread` calls across the program.
- Records: `#record` names a heap layout and generates its typed wrappers, so offsets are never hand-assigned. Each field is `name Type count`, where Type is one of the §2 type tags and count is a positive integer:
  ```scrooge
  #record State
    grid Scalar 81
    rowm Scalar 9
    lat  Ptr    1
  end
  ```
  generates ordinary words: `State_size ( -- n:Scalar )` (91), `State_new ( -- s:Ptr )` (`91 hnew`), and per field a getter and a setter, `State_grid ( s:Ptr i:Scalar -- v:Scalar )` and `State_grid_set ( v:Scalar s:Ptr i:Scalar -- )`. A count-1 field has no index: `State_lat ( s:Ptr -- v:Ptr )`, `State_lat_set ( v:Ptr s:Ptr -- )`. Every field also gets `State_grid_off ( -- n:Scalar )`, the cell where it starts (0 for grid, 81 for rowm, 90 for lat), for the words that take a raw offset: `0 s State_rowm_off 9 hfill` (clear rowm), `hmove`, `hsort`, `fread_into`. Fields are laid out in order (grid at cells 0-80, rowm at 81-89, lat at 90), so they cannot overlap. The accessors are `+ hread` / `+ hwrite` wrappers like the one above: the field type is the same unchecked assertion, and an index is not checked against the field's count (only against the whole allocation, as for any `hread`). Each record is its own allocation, since a `Ptr` cannot be offset. A word named `record` is still an ordinary definition: `#record (` starts a signature, `#record Name` a declaration.

═══ 6. Bracketed Values Are Data ═══
- A `[ ... ]` written as a value (anything that is not a cond branch, a frame body, or a map/fold) is a DATA literal: it may contain only literals (numbers, strings, `nil`) and other such `[ ... ]`, nested to any depth: `[ 1 [ 2 3 ] "ab" nil ]` is valid. Anything else inside it (a word, a variable, a binding, a cond) is a ParseError, with or without nesting: `-> [ x y ] [ [ x y ] ]` is rejected. Build a Block from computed values with `cons` or `pair` (or `block_set` on a literal of the right shape).
- Cond branches, frame bodies and map/fold bodies are code, not values, and nest freely to any depth. Moving an inner loop or conditional into a named helper word is good style (it names the step and keeps each word short), not a rule.

═══ 7. Primitives ═══
- Explicit Float Cast: `to_float` ( Scalar -- Scalar ).
- Absolute Value: `abs` ( Scalar -- Scalar ). Min/Max: `min`, `max` ( Scalar Scalar -- Scalar ).
- Stack Shufflers: `dup` ( x -- x x ) | `drop` ( x -- ) | `swap` ( x y -- y x ) | `rot` ( x y z -- y z x ) | `over` ( x y -- x y x ).
- Block Build: `cons` ( x block -- block' ) | `pair` ( a b -- [a b] ) | `nil` ( -- [] ) | `len` ( block -- n ). | `block_slice` ( b:Block start:Scalar stop:Scalar -- b2:Block ), the elements at indices start <= i < stop as a new Block; bounds clamp to the Block, and start >= stop gives an empty Block. O(stop - start).
- Math: `+`, `-`, `*` | `/` | `\` (remainder). With two integers, `/` TRUNCATES toward zero ("-7 2 /" is -3, as in C) and `\` is the FLOORED remainder, with the sign of the divisor ("-7 2 \" is 1, "7 -2 \" is -1), so the two do not pair up for negative operands. With a float operand, `/` divides as floats; `\` needs integers. Division or remainder by 0 is a fatal error. Integer `+`, `-`, `*` wrap around on overflow (two's complement, 64-bit). An operand that is not a number (a Block, a Ptr) is a fatal error at run time.
- Bitwise (integer operands only): `bitand`, `bitor`, `bitxor`, `bitshl`, `bitshr` ( Scalar Scalar -- Scalar ). "x n bitshl" and "x n bitshr" shift the 64-bit pattern; `bitshr` is LOGICAL (zero-filling: "-8 1 bitshr" is 9223372036854775804; use `/` for an arithmetic shift). A count of 64 or more gives 0; a negative count is a fatal error (it is always a bug, e.g. "1 d 1 - bitshl" with d=0) | `bitnot` ( Scalar -- Scalar ) | `bitcount`, `bitctz`, `bitclz` ( Scalar -- Scalar ): the number of set bits, trailing zero bits and leading zero bits of the 64-bit pattern (a negative number has bit 63 set); `bitctz` and `bitclz` of 0 are 64.
- Compare: `=`, `!=`, `>`, `<`. (`>=` and `<=` are in `library/util.sg`). `<` and `>` compare numbers; an operand that is not a number is a fatal error at run time. To order Blocks, use `sort_cmp` ( a:Unknown b:Unknown -- c:Scalar ): -1, 0 or 1 in `hsort`'s order (element by element, a shorter Block first when it is a prefix of the other, numbers before Blocks), so two strings compare in byte order ("\"ab\" \"b\" sort_cmp" is -1). `=` and `!=` accept any two values: numbers compare by value (an integer equals a float of the same value), Blocks element by element (the same length and every pair of elements equal, recursively; a string is a Block, so this compares strings), Ptrs by identity (the same allocation), and values of different kinds are unequal. `>` and `<` compare numbers.
- Logic: `and`, `or` (eager, both operands evaluated) | `not` ( 1 if input is 0 ).
- I/O: `print_char` ( ascii -- ) | `print_int` ( int -- ) | `print_float` ( x:Scalar decimals:Scalar -- ), a number with 0 to 17 decimals, formatted as C's printf %.*f (so -0.5 with 0 decimals prints -0). Fixed-point and zero-padded integers: print_fixed and int_to_str_pad in the strings lexicon.
- Files: `fopen` ( path:Block mode:Scalar -- fh:File ok:Scalar ) | `fclose` ( fh:File -- ok:Scalar ) | `fgetc` ( fh:File -- ch:Scalar ok:Scalar ) | `fputc` ( ch:Scalar fh:File -- ok:Scalar ) | `fread` ( fh:File n:Scalar -- str:Block ) | `fwrite` ( str:Block fh:File -- written:Scalar ) | `freadline` ( fh:File -- line:Block got:Scalar ) | `fread_into` ( fh:File p:Ptr start:Scalar count:Scalar -- got:Scalar ) | `fseek` ( fh:File pos:Scalar -- ok:Scalar ) | `ftell` ( fh:File -- pos:Scalar ). See §12.
- Command line and environment: `argc` ( -- n:Scalar ) | `argv` ( i:Scalar -- arg:Block ok:Scalar ) | `getenv` ( name:Block -- value:Block ok:Scalar ), read-only. See §13.
- Clock: `clock_ns` ( -- ns:Scalar ), nanoseconds from a monotonic clock. The epoch is arbitrary, so only the difference of two readings means anything: read it before and after the work and subtract.
- Heap Arena: `hmark` ( -- mark:Scalar ) | `hrelease` ( mark:Scalar -- ) | `hsort` ( p:Ptr start:Scalar count:Scalar -- ): sorts the cells start to start+count-1 ascending, in place, stably. Numbers are ordered as `<` orders them; a Block is ordered element by element (a shorter Block first when it is a prefix of the other), so strings sort in byte order and rows column by column; every number sorts before every Block. A cell holding a Ptr (at any depth), or a range outside the allocation, is a fatal error. The util lexicon's block_sort uses the same order. See §5.
- Runtime errors: a fatal error at run time (an out-of-range `hread`, "Modulo requires integers", "Max frames exceeded", ...) prints `Fatal: ...` and then the words that were running, innermost first, each as "in #word (defined line N)" ("strings.sg line N" for a library word), ending "in top level"; the program exits with status 1. A word that calls no other word is not tracked, so a fault inside one is shown in its caller.
- Debugging: `trace` ( v:Unknown -- ) prints the line "trace line N: " and then the value to stderr (after flushing stdout), for a value of any type: a Block shows its first 64 elements, and as text when every element is a printable character; a Ptr shows its size. N is the line of the `trace` in the program's own file. For invariants, the util lexicon has an assert word, ( ok:Scalar msg:Block -- ), which aborts with msg when ok is 0 (§8).
- Numbers and types: `to_int` ( x:Scalar -- n:Scalar ) truncates a float toward zero (an integer passes through; NaN, infinity or a float outside the 64-bit range is fatal); `float_to_str` ( x:Scalar decimals:Scalar -- s:Block ) is the text print_float would print (0-17 decimals); `type_of` ( v:Unknown -- t:Scalar ) is 0 for an integer, 1 a float, 2 a Block, 3 a Ptr (a File handle is an integer).
- `hnull` ( -- p:Ptr ) is a Ptr that refers to nothing, for an absent link in a heap structure: it equals only another hnull (test with "p hnull ="), and hread/hwrite through it are fatal.
- Exit: `exit` ( code:Scalar -- ) ends the program with that status (0-255), flushing stdout first; like `abort` it never returns, so a cond branch ending in it is exempt from branch matching.
- Abort: `abort` ( Block -- ), never returns. Prints its Block argument to stderr as characters and terminates the process with a nonzero exit status. A cond branch whose terminal call is `abort` is exempt from the "branches MUST match in count and type" rule (§10): the checker unifies on the OTHER branch's stack effect/type instead, since the aborting branch never produces a value.

A `use` that names neither a lexicon nor a module file is a ParseError. Module names must differ from the library lexicons' names.
Import at file top; names resolve only for imported lexicons. Each public word is listed with its signature; `library/manifest.sm` has the same signatures with a one-line description of each word, and one `prim` line per primitive. Check it before writing a helper: the word may already exist.

═══ 9. Track 2 Static Verification & Error Classes ═══
Warnings (on stderr after ACCEPT, never a rejection): `MutualRecursion` for a loop written as a cycle of tail calls (§3), and `AliasShadowsWord` for a frame alias spelled like one of the program's own words, which hides that word until the end of the block.
A REJECT lists every error found, in source order, and the compiler exits with status 1 (ACCEPT: 0); a build that is rejected removes any earlier binary at the output path, so a stale program is never left to be run by mistake. Words with a stack-effect error are not type-checked, but every other word is, in the same run.
Static checker enforces:
- `ArityMismatch`: Signature vs body net effect mismatch, signature vs frame input count mismatch, or unequal cond branches.
- `TypeError`: Tagged parameter call-site type mismatch, `_at` indexing into `Ptr`/`Record`/`Scalar`/`File`, or a signature declaring an unrecognized type tag (§2).
- `UnknownWordError`: Invocation of an undeclared word or primitive, in a word body or in top-level code. When a library lexicon defines the word, the message names it and the `use` line to add.
- `ParseError`: Unterminated brackets, missing signature parentheses, a `[ ... ]` value containing code (§6), a frame with no `[ names ]` after `->`, a malformed `cond`, a stray `?`/`else` that no `cond` claims, an `end` outside any definition, or a definition with no `end`. Cond-related ParseErrors report `line L col C` and name the cond they concern.
- `ReservedWordIdentifierError`: Reserved word used as a parameter name, a frame alias, or the name of a `#word` definition (when it is not a primitive; see `DuplicateWordError`).
- `DuplicateWordError`: Local `#word` definition shadowing a builtin primitive, a `use`-imported lexicon word (the message names the lexicon), or a duplicate local word definition.

═══ 10. Hard Rules (violations are rejected) ═══
- Reserved words — never use as parameter name or frame alias: use lexicon to from and or not cond else map fold pk roll select nil cons pair end dup drop swap rot over fill len seed rand exp log pow sqrt abs max min to_float bitand bitor bitxor bitshl bitshr bitnot hnew hread hwrite print_char print_int abort hmark hrelease fopen fclose fgetc fputc fread fwrite argc argv clock_ns block_slice bitcount bitctz bitclz hsort print_float getenv freadline fread_into fseek ftell trace hmove hfill exit to_int float_to_str type_of hnull when unless sort_cmp.
  - Of these, `to`, `fill`, `seed`, `rand`, `exp`, `log`, `pow`, `sqrt`, `roll`, and `pk` have NO current implementation in either backend — using any of them as a word is rejected as `UnknownWordError`, the same as any other undeclared word. They remain reserved so a future implementation is a small, isolated addition rather than a breaking change to existing programs.
- Never shadow your own word names or imported lexicon words with a local definition or alias.
- `cond` condition expression MUST NOT be enclosed in brackets `[ ... ]`.
- `cond` branches MUST match in count and type, except when exactly one branch's terminal call is `abort`: that branch is exempt, and the other branch's effect/type is used (§7). An omitted else-branch counts as `[ ]`.
- A `[ ... ]` value contains only literals and other such values (§6).
- `_at` only on homogeneous collections; never index a record.
- `_get`/`_set` only on `Block`/`Record`; never on `Ptr` or `Scalar`.
- `_set` may replace a slot's value only with a value of the SAME type — never change shape or type. Enforced by Track 2 wherever both the slot's current type and the incoming value's type are statically known; unchecked when either is `Unknown`.
- Pointers are opaque — no pointer arithmetic (`ptr 1 +`).
- `and`/`or` are eager — guard risky paths with `cond`, not `and`/`or`.

═══ 11. Worked Examples ═══
Fold to a scalar:
```scrooge
#sum ( block:Block -- total:Scalar )
  -> [ block ] [ block [fold| idx acc val _ | acc val + from 0 ] ]
end
```

Map over a block:
```scrooge
#double_all ( block:Block -- doubled:Block )
  -> [ block ] [ block [map| idx val _ | val 2 * ] ]
end
```

Fold building a block ('from nil'):
```scrooge
#copy_reverse ( block:Block -- reversed:Block )
  -> [ block ] [ block [fold| idx acc val _ | val acc cons from nil ] ]
end
```

Tail-recursive loop:
```scrooge
#fact_iter ( n:Scalar acc:Scalar -- r:Scalar )
  -> [ n acc ] n 0 =
  cond [ acc ] else [ n 1 - n acc * fact_iter ] ?
end
#fact ( n:Scalar -- r:Scalar )
  -> [ n ] [ n 1 fact_iter ]
end
```

Float conversion before division:
```scrooge
#avg_calc ( total:Scalar count:Scalar -- avg:Scalar )
  -> [ total count ] [ total to_float count to_float / ]
end
```

Typed-heap-wrapper (confines the `hread` type-erasure boundary to one named word, per §5):
```scrooge
#row_at ( tbl:Ptr idx:Scalar -- row:Block )
  -> [ tbl idx ] [ tbl idx hread ]
end
```

Abort on an unreachable branch (per §7/§10, the aborting branch is exempt from the cond stack-effect match):
```scrooge
#safe_div ( a:Scalar b:Scalar -- r:Scalar )
  -> [ a b ] b 0 =
  cond [ [ 68 105 118 32 98 121 32 122 101 114 111 ] abort ] else [ a b / ] ?
end
```

Sequential file I/O, whole-file and character-at-a-time (per §12):
```scrooge
use "file"
#count_lines_loop ( fh:File n:Scalar -- total:Scalar )
  -> [ fh n ] [ fh n fh fgetc ]
  -> [ fh n ch ok ] ok not
  cond [ n ] else [ fh n ch 10 = + count_lines_loop ] ?
end
#copy_file ( src:Block dst:Block -- ok:Scalar )
  -> [ src dst ] [ dst src f_read_file ]
  -> [ dst text ok ] ok not
  cond [ 0 ] else [ text dst f_write_file ] ?
end
```

Bound heap growth around a unit of work with `hmark`/`hrelease` (per §5):
```scrooge
#process_query ( -- )
  hmark -> [ mark ] [
    10 hnew drop
    mark hrelease
  ]
end
```

═══ 12. File I/O Protocol ═══
- A `File` is an opaque handle, exactly as a `Ptr` is (§5): the checker rejects
  arithmetic on it, `hread`/`hwrite` through it, and `_at`/`_get`/`_set` into
  it. It is produced only by `fopen` and consumed only by the six file
  primitives. The value is not a memory address and carries no length.
- Open: `path mode fopen -> fh ok`. `path` is a Block of character codes (a
  string literal is exactly that). `mode` is 0 read, 1 write (truncating), 2
  append. ok=0 means the open failed -- the file does not exist, permission
  was refused, or every openable handle is already in use -- and `fh` must not
  be used. Prefer `library/file.sg`'s named `f_open_read`/`f_open_write`/
  `f_open_append` over a bare mode integer.
- Close: `fh fclose -> ok`. ok=0 means the handle was already closed, or names
  a standard stream (which this process does not own). Closing flushes.
- Handles 0, 1 and 2 are pre-opened as stdin, stdout and stderr, so the same
  read and write words serve the standard streams; `file.sg` names them
  `f_stdin`/`f_stdout`/`f_stderr`. Output to stdout is buffered: `print_char`,
  `print_int`, `print_float` and writes to handle 1 share one buffer, so they
  stay in order. It is flushed before anything is written to stderr (so an
  error or `abort` message still follows the output before it), before a
  read from stdin (so a prompt is visible), and at exit. A real file stays
  buffered until it is closed or the process exits normally.
- Sequential read, two granularities:
    `fh fgetc -> ch ok`        one character; ok=0 at end of input (ch=0)
    `fh n fread -> str`        up to n characters as a Block; `str len` is how
                               many were actually read, and an empty Block
                               means end of input
    `fh freadline -> line got` the next line, in one pass; the newline is
                               consumed, not returned; got=0 only at end of
                               input with nothing read
    `fh p start n fread_into -> got`
                               up to n bytes into heap cells start.. of p, each
                               an integer 0-255; got is how many (0 at end of
                               input). No Block is built, so a large file can
                               be streamed through a fixed heap buffer
  Use `freadline` (or `f_read_line`) for line-structured text, `fread_into` or
  `fread` for throughput, and `fgetc` only when the read must stop at some
  other delimiter: a Scrooge-level per-character loop pays a word call and a
  `cons` copy per character.
- Sequential write, the same two granularities:
    `ch fh fputc -> ok`        one character; ok=0 on a write error
    `str fh fwrite -> written` every character of str; written < `str len`
                               means the write failed part way
- Partiality is always reported through a Scalar flag or a length, never by
  aborting -- the same convention as `lst_try_push`, `map_set` and
  `str_to_int`. Only an outright protocol violation is fatal: a non-File where
  a File is required, a closed handle, a non-Block path, a negative `fread`
  count, a negative `fseek` position, or a `fread_into` range outside the
  allocation. This mirrors `hread`/`hwrite`.
- Position: `fh pos fseek -> ok` moves to an absolute byte offset (ok=0 when
  the stream cannot seek, e.g. a pipe; a negative pos is fatal);
  `fh ftell -> pos` is the current offset, -1 when the stream has none.
- Cost model: a file read into a Block costs one Block slot per character, and
  a Block slot is considerably wider than a byte. `f_read_all` materializes an
  entire file that way, which is the right thing for configuration and data
  files and the wrong thing for something far larger than memory -- stream
  such input with `fread` a chunk at a time instead of accumulating it.
- The number of simultaneously open handles is fixed and small (61 beyond the
  three standard streams). Close what you open; exhaustion surfaces as
  `fopen`'s ok=0, not as a crash.

═══ 13. Command-Line Arguments ═══
- `argc ( -- n:Scalar )` is the number of command-line arguments, and
  `argv ( i:Scalar -- arg:Block ok:Scalar )` is the i-th one as a Block of
  character codes. A string literal is exactly such a Block, so an argument
  compares and prints like any other string.
- **The indexing is C's, exactly.** `0 argv` is the program as invoked; the
  first real argument is `1 argv`; `argc` counts both, so it is 1 for a
  program run with no arguments. Nothing is re-based: an index means the same
  thing here as in the `argc`/`argv` of the process itself.
- ok=0 means there is no argument at that index (and the Block is empty). That
  is the ordinary way to ask "was this argument supplied?", so it is a flag
  rather than an abort, exactly as with `fopen`/`fgetc` (§12). A negative index
  is likewise ok=0, not an error. An argument that was supplied but is empty --
  `prog ""` -- returns an empty Block with **ok=1**: present and empty is not
  the same as absent.
- Only a non-integer index is fatal, matching `hread`/`fread`.
- Nothing is materialized up front. A program that never asks pays nothing;
  one that asks for argument 3 allocates that one string. `library/args.sg`'s
  `arg_tail` is the word that deliberately materializes all of them.
- Arguments are read-only. There is no way to alter them.
- The environment is readable, not writable: `getenv` ( name:Block --
  value:Block ok:Scalar ) has argv's shape, ok=0 and an empty Block for an
  unset variable, ok=1 and the value (possibly empty) for a set one.
  `library/file.sg`'s `f_expand_home` turns a leading `~/`, or a lone `~`,
  into $HOME, leaving any other path unchanged.
- `library/args.sg` (§8) adds the words worth having on top: `arg_prog`,
  `arg_or` (a total accessor taking a default, so no flag reaches the call
  site), `arg_tail` (the arguments without the program name, as a Block of
  Blocks, for `[fold| ... ]`), and `arg_find` (the C index of the first
  argument equal to a given string -- flag scanning), plus flag parsing:
  `arg_flag` (was the flag given), `arg_value_or` (the argument after the
  flag, or a default when it is absent or last) and `arg_int_or` (that value
  as an integer, or a default when absent or not an integer).

Worked example -- greet each argument, or the world if there are none:
```scrooge
use "args"
use "strings"
#greet_step ( idx:Scalar acc:Scalar val:Block ctx:Scalar -- acc2:Scalar )
  -> [ idx acc val ctx ] [ "Hello, " str_print val str_print 10 print_char acc ]
end
#main ( -- )
  arg_tail -> [ args ] args len 0 =
  cond [ "Hello, world" str_print 10 print_char ] else [
    args [fold| idx acc val _ | idx acc val 0 greet_step from 0 ] drop
  ] ?
end
main
```
