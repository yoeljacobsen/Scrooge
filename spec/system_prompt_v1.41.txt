Coding Rules & Anti-Patterns
═══════════════════════════════════════════════════════════════════════════
- Unbracketed Frames: Variables and body must both be bracketed. '-> [ x ] x 1 +' is a parse error; write '-> [ x ] [ x 1 + ]'.
- Missing 'cond' Keyword: Conditionals must explicitly use 'cond'. 'flag [ t ] else [ f ] ?' is invalid; write 'flag cond [ t ] else [ f ] ?'.
- Reserved Word Parameters: Never use primitive names or keywords (e.g., 'end', 'pair', 'nil') as parameters or frame aliases. Use non-reserved alternatives ('stop', 'pr').
- Pointer Arithmetic: Pointers are opaque tokens. 'ptr 1 +' is a type check violation. Compute integer offsets first, then pass to memory primitives ('ptr offset hread').
- Nested Data Literals: '[ 1 [ 2 3 ] ]' evaluates as a deferred closure, not a data array. Build nested or tree structures dynamically at runtime using 'cons' and 'pair'.
- Nested Loop Brackets: Iterators cannot contain internal nested brackets. Conditional branching or nested loops within an iterator body must be extracted into independent, named words.
- Unequal Branch Effects: Both branches of a 'cond' block must yield the exact same net stack arity and type effect.
- Eager Logic Evaluation: 'and' and 'or' evaluate both operands eagerly before executing. Do not use them as short-circuiting guards; use 'cond' to isolate guarded or risky execution paths.

1. Core Grammar, Syntax & Modularity
═══════════════════════════════════════════════════════════════════════════
- Zero-Nesting Rule: No opening square bracket '[' may appear inside another active bracket pair. Structural nesting depth within any block is strictly capped at 1. Sibling blocks are permitted.
- Word Definitions: Written as '#name ( inputs -- outputs ) body end'. Signatures verify arity and types but do not bind names. Parameters referenced by name in a body must be bound by an initial arrow frame.
- Arrow Frames: Sibling scope chaining allows consecutive frames to inherit unshadowed aliases. Trailing conditional branches inherit the active frame's scope.
- Modular Imports: 'use "lexicon_name"' statements at the top of a file are stripped from the executable token stream. They inject only the specific word signatures matched to that lexicon name from the master manifest, enforcing strict namespace isolation.

═══════════════════════════════════════════════════════════════════════════
2. Dual-Track Static Verification
═══════════════════════════════════════════════════════════════════════════
- Track 1 (Arity): Statically computes the net push/pop count of a word body, which must match its signature. Literals contribute +1; primitives have fixed effects. Unknown words cause a validation halt.
- Track 2 (Coarse Types): Tracks stack slots using four static tags: Scalar, Block, Ptr, and Unknown. Mixed-mode math promotes Int to Float. Primitives enforce rigid type constraints (+ requires two Scalars; : requires Block and Scalar; hread requires Ptr and Scalar). Unknown bypasses type constraints without throwing false positives.
- Type-Checker Guidance: Track 2 does not propagate type states across stack shufflers ($, @, roll, pk). Use explicit '-> [ ... ]' variable frames to isolate and name structural elements during complex stack operations.
- Tail-Call Optimization (TCO): Terminal self-recursion and mutual recursion (including inside terminal conditional branches) are flattened into iterative loops. Loops must be written as tail-recursive words rather than core grammar constructs.
- Context Iterators: 
  * '[map| idx val ctx | body ]' requires a body effect of ( idx val -- val' ) [net +1].
  * '[fold| idx acc val ctx | body from init ]' requires a body effect of ( idx acc val -- acc' ) [net +1]. The return type is inferred from the inline 'init' token ('from 0' -> Scalar; 'from nil' -> Block). Fold 'init' expressions evaluate before loop aliases are bound; the 'ctx' register is out of scope within the 'from ...' block.

═══════════════════════════════════════════════════════════════════════════
3. Data Types & Registry Constants
═══════════════════════════════════════════════════════════════════════════
- Scalar: Signed 64-bit integers or floating-point mantissas (e.g., 314e-2). 
- Strings: Double-quoted string literals (e.g., "Hello") are fully supported. They are expanded during pre-compilation into standard Block arrays of ASCII decimal scalars (e.g., [ 72 101 108 108 111 ]).
- Logic Operators: Only '=', '!=', '>', and '<' are valid primitives. No '>=' or '<=' operators exist; range checks must use shifted integer boundaries (e.g., '>= 48' must be written as 'ch 47 >').
- Comments: '{' and '}' are whitespace-isolated tokens. Text within them is ignored only when the delimiters stand independently as separate tokens.

4. Primitive Operator Registry & Semantics
═══════════════════════════════════════════════════════════════════════════
Stack Shufflers & Structural Primitives:
- .           [+1] ( x -- x x ) Duplicate the top item on the stack.
- %           [-1] ( x -- ) Drop the top item from the stack.
- $           [0]  ( x y -- y x ) Swap the positions of the top two stack items.
- @           [0]  ( x y z -- y z x ) Rotate the top three stack items (lift x).
- ;           [+1] ( x y -- x y x ) Duplicate the second stack item to the top.
- roll        [0]* ( ... idx -- ... ) Pop compile-time literal index N; lift stack item at depth N to the top.
- pk          [+1]*( ... idx -- ... x ) Pop compile-time literal index N; copy stack item at depth N to the top.
- cons        [-1] ( x block -- [x ...block] ) Prepend element x to the front of a block array.
- pair        [-1] ( car cdr -- [car cdr] ) Construct a native two-element array from car and cdr.
- len         [0]  ( block -- length ) Return the total structural element count of a block.
- nil         [+1] ( -- [] ) Push an empty immutable block array literal to the stack.

Collection Retrieval & Control:
- :           [-1] ( block idx : -- elem ) Retrieve array element at index, or terminate a slice.
- to          [-1] ( block start to end : -- slice ) Mark boundaries for block slicing; upper bound exclusive.
- select      [-2] ( vt vf flag -- choice ) Return vt if scalar flag is non-zero, otherwise return vf.

Heap Allocations & Streaming I/O:
- hnew        [0]  ( size -- ptr ) Allocate a flat sequence of clear data cells on the heap.
- hread       [-1] ( ptr idx -- val ) Read cell value from a heap pointer at specified cell index.
- hwrite      [-3] ( val ptr idx -- ) Write scalar or token value into a heap cell at specified cell index.
- print_char  [-1] ( ascii -- ) Write integer scalar as a single ASCII character directly to stdout.
- print_int   [-1] ( int -- ) Format and write signed integer scalar text directly to stdout.

Math & Logic Operators:
- + - *       [-1 each] Standard addition, subtraction, and multiplication arithmetic.
- /           [-1] Floor division if both integers are integers; IEEE float division if either is Float.
- \           [-1] Arithmetic modulo operation.
- and or      [-1 each] Logical conjunction and disjunction; return scalar 1 or 0.
- not         [0]  Logical inversion; return scalar 1 if input is exactly 0, otherwise return 0.
- = != > <    [-1 each] Structural/scalar equality and comparisons; return scalar 1 if true, 0 if false.

Core Library Reference:
- exp, log, pow, sqrt, abs, max, min: Standard single or double argument math functions.
- fill        [-1] ( length value fill -- block ) Pre-populate an array block with a repeated value.
- seed        [-1] ( int -- ) Set the internal pseudo-random number generator state seed.
- rand        [+1] ( -- float ) Generate a pseudo-random floating-point scalar between 0.0 and 1.0.
- bitand, bitor, bitxor, bitnot: 64-bit bitwise masking and inversion functions.
- bitshl, bitshr: 64-bit logical bitwise left and right shifting operators.

*Arguments for 'roll' and 'pk' must be immediate compile-time literals.
